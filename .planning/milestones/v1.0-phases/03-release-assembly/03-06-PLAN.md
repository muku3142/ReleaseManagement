**Create `ManualItemRequest`** in `com.evision.releasemgmt.adapters.web.dto`. `category` is typed
as the domain enum, so Jackson rejects any value outside the four with a deserialisation failure
that surfaces as a 400 — the category can never reach the database as an unrecognised string
(D-03-03):
```java
public record ManualItemRequest(
        @NotBlank @Size(max = 200) String title,
        @Size(max = 5000) String description,
        @NotNull ManualItemCategory category) {
}
```
`description` is optional — a one-line "Run the index rebuild script" item needs no body — but is
capped. A null description is stored as an empty string, never as SQL NULL, because the column is
`NOT NULL`.

**Add three methods to `ReleaseService`**, each guarded by `requireOpen()` exactly like the
ticket-item methods from plan 03-04 (D-03-13: manual items are editable while OPEN and frozen
thereafter, the same rule as ticket-backed items):
```java
public Release addManualItem(UUID releaseId, String title, String description,
                             ManualItemCategory category) {
    get(releaseId).requireOpen();
    ManualItem item = ManualItem.create(title.trim(), nullToEmpty(description), category,
            Instant.now());
    return repository.addManualItem(releaseId, item);
}

public Release updateManualItem(UUID releaseId, UUID manualItemId, String title,
                                String description, ManualItemCategory category) {
    get(releaseId).requireOpen();
    // addedAt is carried by the stored row and deliberately not overwritten here - editing an
    // item does not change when it joined the release. The adapter's updateManualItem only
    // copies title, description and category across.
    ManualItem item = new ManualItem(manualItemId, title.trim(), nullToEmpty(description),
            category, null);
    return repository.updateManualItem(releaseId, item);
}

public Release removeManualItem(UUID releaseId, UUID manualItemId) {
    get(releaseId).requireOpen();
    return repository.removeManualItem(releaseId, manualItemId);
}

private static String nullToEmpty(String value) {
    return value == null ? "" : value.trim();
}
```

**Add three endpoints to `ReleaseController`**, reusing the existing private `toResponse(Release)`
mapper:

| Method | Path | Body | Success |
|---|---|---|---|
| `POST` | `/api/releases/{releaseId}/manual-items` | `ManualItemRequest` | `201` `ReleaseResponse` |
| `PUT` | `/api/releases/{releaseId}/manual-items/{manualItemId}` | `ManualItemRequest` | `200` `ReleaseResponse` |
| `DELETE` | `/api/releases/{releaseId}/manual-items/{manualItemId}` | — | `200` `ReleaseResponse` |

```java
@PostMapping("/{releaseId}/manual-items")
@ResponseStatus(HttpStatus.CREATED)
public ReleaseResponse addManualItem(@PathVariable UUID releaseId,
                                     @Valid @RequestBody ManualItemRequest request) {
    return toResponse(service.addManualItem(releaseId, request.title(), request.description(),
            request.category()));
}

@PutMapping("/{releaseId}/manual-items/{manualItemId}")
public ReleaseResponse updateManualItem(@PathVariable UUID releaseId,
                                        @PathVariable UUID manualItemId,
                                        @Valid @RequestBody ManualItemRequest request) {
    return toResponse(service.updateManualItem(releaseId, manualItemId, request.title(),
            request.description(), request.category()));
}

@DeleteMapping("/{releaseId}/manual-items/{manualItemId}")
public ReleaseResponse removeManualItem(@PathVariable UUID releaseId,
                                        @PathVariable UUID manualItemId) {
    return toResponse(service.removeManualItem(releaseId, manualItemId));
}
```
All three return the whole `ReleaseResponse` so the detail screen can replace its cached release in
one hop, matching the ticket-item endpoints from plan 03-04. None takes a `Principal`: D-03-12
records the actor on release creation and freeze only, and there is no `added_by` column on a
manual item — do not add one.

Make no change to `SecurityConfig`: `/api/**` is already `authenticated()`. Do not add a
`ManualItemController` — three endpoints on an existing sub-resource do not warrant a second
controller.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> `/api/releases/{id}/manual-items` | Manual-item title and description are wholly user-authored free text, unlike ticket snapshots which at least originate from Jira |
| Path parameters -> stored rows | A manual item is addressed by a UUID in the URL alongside its release's UUID |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-35 | Tampering | Category value reaching storage | mitigate | `ManualItemRequest.category` is typed as the `ManualItemCategory` enum, so an unknown value fails Jackson deserialisation and returns a 4xx; the domain enum, the JPA `@Enumerated(EnumType.STRING)` mapping and V3's `CHECK (category IN (...))` are three independent gates on the same four values (D-03-03) |
| T-03-36 | Tampering | Editing an item through the wrong release | mitigate | The adapter's `updateManualItem`/`removeManualItem` resolve the row with `findByReleaseIdAndId` (plan 03-02), so a guessed item UUID supplied under a different release id resolves to nothing rather than to another release's item |
| T-03-37 | Tampering | Writing to a frozen release | mitigate | All three service methods call `Release.requireOpen()` before touching the repository. Three service tests and three controller tests assert the 409, so hiding the form in the UI (plan 03-08) is defence in depth, not the control (D-03-13) |
| T-03-38 | Denial of service | Oversized manual-item payloads | mitigate | `@Size(max = 200)` on title and `@Size(max = 5000)` on description, rejected as `VALIDATION_FAILED` before the service runs; `VARCHAR(200)` on the title column is the storage-level backstop |
| T-03-39 | Tampering | Stored XSS via manual-item text | mitigate | Text is stored verbatim and never interpreted server-side. The release detail screen renders it as a JSX text child, which React escapes, and no `dangerouslySetInnerHTML` exists (plan 03-05 grep gate). Phase 5's document rendering is separately constrained to a logic-less engine with no expression language |
| T-03-40 | Repudiation | No actor recorded on a manual item | accept | D-03-12 scopes actor recording to release creation and freeze; V3 has no `added_by` column on `release_manual_item` and adding one now would be building for an audit view that does not exist until Phase 7. The frozen snapshot remains the audit artefact this phase promises |
</threat_model>
