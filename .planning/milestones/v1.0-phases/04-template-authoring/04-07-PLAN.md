Backend contract this module wraps (plans 04-04 and 04-05):

```
GET    /api/templates                            -> { templates: TemplateSummaryResponse[] }
POST   /api/templates                            -> 201 TemplateResponse   body {name, documentType}
GET    /api/templates/catalog                    -> { entries: [...], logoLimits: {...} }
GET    /api/templates/render-context/{releaseId}  -> ReleaseView
GET    /api/templates/{id}                       -> TemplateResponse
PUT    /api/templates/{id}/name                  -> TemplateResponse   body {name}
PUT    /api/templates/{id}/content               -> TemplateResponse   body {body, chrome:{...}}
POST   /api/templates/{id}/activate              -> TemplateResponse
POST   /api/templates/{id}/duplicate             -> 201 TemplateResponse
DELETE /api/templates/{id}                       -> 204
POST   /api/templates/{id}/logo                  -> TemplateResponse   multipart field "file"
DELETE /api/templates/{id}/logo                  -> TemplateResponse
GET    /api/templates/{id}/logo                  -> image bytes
```

Response shapes:
```
TemplateSummaryResponse { id, name, documentType, active, hasLogo, warningCount, updatedAt }
TemplateResponse        { id, name, documentType, body, active,
                          chrome: { coverEnabled, coverTitle, coverSubtitle,
                                    headerText, footerText, pageNumbersEnabled },
                          logo: { contentType, filename, byteSize, width, height, uploadedAt } | null,
                          warnings: string[], createdAt, createdBy, updatedAt, updatedBy }
PlaceholderCatalogResponse { entries: [{ scope, token, kind, description, tags }],
                             logoLimits: { maxBytes, maxWidth, maxHeight, contentTypes } }
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `/api/templates` | Every template write from the SPA crosses here and must carry the CSRF echo |
| API response → React DOM | Template names, warning strings and `ProblemDetail` details are rendered into the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-35 | Tampering | CSRF on a template create/delete | mitigate | Every call goes through `apiFetch`, which echoes the `XSRF-TOKEN` cookie into `X-XSRF-TOKEN` on non-GET requests; the FormData guard added here changes only the content-type line and leaves the CSRF block untouched |
| T-04-36 | Elevation of Privilege | XSS through a template name or a backend `detail` string rendered in the list | mitigate | Every string is rendered as a React text child, never through `dangerouslySetInnerHTML` — this plan introduces no HTML injection point at all (the preview's single justified use arrives in plan 04-08) |
| T-04-37 | Information Disclosure | A raw backend error leaking into the UI | mitigate | All error copy is selected by `messageForReason(problem)` keyed on the machine-readable `reason`, extending the Phase 01 table rather than rendering arbitrary server text |
| T-04-38 | Spoofing | A signed-out user reaching `/templates` | mitigate | The route nests under `authenticatedRoute`, whose `beforeLoad` redirects to `/login` when there is no session — unchanged from every other authenticated route |
| T-04-39 | Denial of Service | A multipart upload silently failing and being retried in a loop | mitigate | The `instanceof FormData` guard makes the upload parseable server-side; the regression is pinned by an API-module test asserting the header is not set |
</threat_model>
