**Module setup**, at the top of the file, outside the component:
```tsx
import Mustache from 'mustache';
import MarkdownIt from 'markdown-it';

// D-04-05 on the client: html:false makes markdown-it escape raw HTML rather than pass it through,
// which is the same posture the backend takes with flexmark. UI-SPEC treats an inability to suppress
// raw HTML as a blocking library-selection defect, so this option is not negotiable.
const md = new MarkdownIt({ html: false, linkify: false, typographer: false });

// D-04-05 again: mustache.js HTML-escapes interpolated values by default, which would turn an
// ampersand in a ticket summary into a visible &amp; once markdown-it escapes it a second time.
// Escaping happens exactly once, in markdown-it.
Mustache.escape = (value) => String(value);

// TMPL-05's client-side counterpart. Not the server's bound - the server refuses; the preview
// truncates and says so, because a half-typed template rendered against a 900-item release is a
// preview practicality, not a defect in the author's template.
const PREVIEW_ITEM_CAP = 200;
```

**Context builder** — mirror `RenderContextMapper` key-for-key:
```tsx
function toContext(view: ReleaseView) {
  const cap = (items: ItemView[]) => items.slice(0, PREVIEW_ITEM_CAP);
  return {
    release: {
      name: view.name, version: view.version, status: view.status,
      jiraProjectKey: view.jiraProjectKey, createdAt: view.createdAt,
      frozenAt: view.frozenAt, lastRefreshedAt: view.lastRefreshedAt,
    },
    items: cap(view.items),
    groups: view.groups.map((g) => ({ groupName: g.groupName, items: cap(g.items) })),
  };
}
```
`ItemView`, `GroupView`, `CommentView`, `CommitView` and `PullRequestView` are already plain JSON
objects with exactly the catalogued field names, so they pass through unchanged.

**Unknown-token marking**, the client half of D-04-08. Build the scope-aware valid-token sets from
`props.entries` (grouping by `scope`), then walk `body` for `{{…}}` tags with the same scope stack the
backend scanner uses (`items` → ITEM, `groups` → GROUP, `comments` → COMMENT, `commits` → COMMIT,
`pullRequests` → PULL_REQUEST, `isManual` → same scope). For every tag whose name is not valid in the
current scope, rewrite exactly as `RenderService.markUnknownTokens` does:
- `{{t}}`, `{{#t}}` and `{{^t}}` → the literal text `[[unknown: t]]`
- the matching `{{/t}}` → the empty string

If the walk hits an unbalanced or unterminated tag, return a `{ ok: false }` result rather than
throwing — see the "preview unavailable" state below.

**Render**, in this order: `Mustache.render(markedSource, context)` → `md.render(markdown)` →
post-process the HTML string to turn the marker text into the chip:
```tsx
// markdown-it has already escaped <, >, & and " in every text node, so the captured token is safe to
// interpolate. This is the one place this app builds HTML by hand, and it is confined to replacing a
// literal marker the renderer itself produced.
const withChips = html.replace(
  /\[\[unknown: ([^\]]*)\]\]/g,
  (_m, token) =>
    `<code class="rounded bg-amber-100 px-1 py-0.5 font-mono text-xs text-amber-900">[[unknown: ${token}]]</code>`,
);
```

**Rendered output container** — the only place `dangerouslySetInnerHTML` is used in this app, and the
only element carrying `prose`:
```tsx
<div className="prose prose-gray max-w-none p-4" dangerouslySetInnerHTML={{ __html: withChips }} />
```
No `prose` class may appear on any surrounding element — the exception is scoped to exactly this
container.

  ```tsx
  </p>
  ```
  Blue, not amber: this is a preview practicality, not a caution about the author's template.

Memoise the whole pipeline with `useMemo` keyed on `[props.body, props.view, props.entries]` so a

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| template body → client renderer | Untrusted template text is compiled and executed in the author's own browser |
| Jira ticket text → rendered preview HTML | Third-party content is interpolated into a string that is injected with `dangerouslySetInnerHTML` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-46 | Elevation of Privilege | XSS through `dangerouslySetInnerHTML` on the rendered preview | mitigate | `markdown-it` is constructed with `html: false`, so raw HTML in the source or in any interpolated value is escaped and never reaches the DOM as markup; asserted from both directions by `TemplatePreview.test.tsx` tests 2 and 3. The mustache layer is configured with a no-op escape so escaping happens exactly once, at the markdown layer |
| T-04-47 | Elevation of Privilege | XSS through the hand-built unknown-token chip | mitigate | The regex operates on markdown-it's *output*, in which `<`, `>`, `&` and `"` are already escaped, so the captured token cannot contain markup; the replacement is confined to a literal marker the pipeline itself produced, and it is the only hand-built HTML in the app |
| T-04-48 | Elevation of Privilege | A template reaching a JS lambda or a prototype property through mustache.js | mitigate | The context is a plain JSON object built from the API response by `toContext`; mustache.js resolves only own/inherited data properties and there are no functions in the context, so there is nothing callable to invoke |
| T-04-49 | Denial of Service | Rendering a 900-item release on every keystroke, freezing the tab | mitigate | `PREVIEW_ITEM_CAP = 200` slices every item collection before rendering and the whole pipeline is `useMemo`d, so a keystroke costs one bounded render |
| T-04-50 | Spoofing | The preview showing something the generated document will not | accept | D-04-10, recorded deliberately: two independent renderers can diverge, no parity mechanism is built, and the mitigation is library choice plus the standing "Preview approximation" notice. The cheap additive fix if it bites is a shared fixture set — do not build it now |
| T-04-51 | Information Disclosure | Supply-chain risk from two new runtime dependencies | mitigate | Exactly two were added, both long-standing reference implementations pinned to exact versions, with `package-lock.json` committed in the same change; an acceptance criterion greps that no third renderer crept in |
</threat_model>
