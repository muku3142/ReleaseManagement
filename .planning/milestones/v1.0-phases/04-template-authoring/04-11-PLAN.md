**`insertToken(token)`** implements UI-SPEC's insert mechanism exactly:
```tsx
function insertToken(token: string) {
  const text = `{{${token}}}`;
  const target = lastFocus;                  // { field, start, end } recorded on blur/select
  if (!target) {                             // nothing focused yet: append to the body and show it
    setTab('body');
    setBody((b) => b + text);
    focusAfterInsert('body', body.length + text.length);
    return;
  }
  if (target.field === 'body') {
    setBody((b) => b.slice(0, target.start) + text + b.slice(target.end));
  } else {
    setChrome((c) => ({ ...c, [target.field]: insertInto(c[target.field], target.start, target.end, text) }));
  }
  focusAfterInsert(target.field, target.start + text.length);
}
```
It inserts at the **last recorded cursor position**, never the field's live DOM selection — focus has
already left the field by the time the drawer row is activated, so the live selection is meaningless.
`focusAfterInsert` re-focuses the target element (via `bodyRef` or a ref map for the four chrome
inputs) and calls `setSelectionRange(caret, caret)` inside a `requestAnimationFrame` so React has
committed the new value first. When nothing has ever been focused, the fallback appends to the body
**and** switches the tab to Body if Chrome & Logo was active — a sensible default rather than a dead
click.

The drawer stays open after every insert.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| catalog API response → drawer DOM | Token names and descriptions come from the backend constant and are rendered into the page |
| drawer insert → template draft | Inserted text becomes part of untrusted template source |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
