<objective>
Make DOC-01 real: an explicit, per-document-type Generate action that renders the active template
against the release and writes an immutable snapshot revision.

Purpose: this is the first user-visible capability of the phase. Everything downstream (exports,
viewer, readiness) reads what this writes. Two load-bearing constraints:
- **Generation must go through `RenderService`, never around it** (D-04-11). `RenderService` owns
  TMPL-05's wall-clock timeout and collection cap; a second render path would silently unbound them.
- **Generation is explicit and per-type, never automatic** (D-05-10). Auto-generating on freeze was
  rejected. A type with zero active templates is a supported state and must surface as a clear
  `NO_ACTIVE_TEMPLATE` conflict, not an error.

Output: `DocumentGenerationService`, `DocumentController` with four endpoints, three DTOs, two new
ProblemDetail reason codes, and tests.
</objective>

```
POST /api/releases/{releaseId}/documents/{documentType}            -> 201 DocumentResponse
GET  /api/releases/{releaseId}/documents/{documentType}            -> 200 DocumentResponse (latest)
GET  /api/releases/{releaseId}/documents/{documentType}?revision=N -> 200 DocumentResponse
GET  /api/releases/{releaseId}/documents/{documentType}/revisions  -> 200 DocumentRevisionListResponse
GET  /api/releases/{releaseId}/documents/{documentType}/logo?revision=N -> 200 image bytes | 404
```
`revision` is a **query parameter, never a path segment** — a `{revision}` path variable would be
ambiguous with the literal `/revisions` segment and bind-fail with a 400.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `/api/releases/{id}/documents/{type}` | Authenticated SPA request crossing into a state-changing action |
| stored template body (untrusted author input) → RenderService | The template author is not trusted (PROJECT.md constraint) |
| stored logo bytes → snapshot copy | Bytes were content-validated at upload (TMPL-09); this path copies them |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-15 | Denial of Service (unbounded render) | `DocumentGenerationService` | mitigate | Body and all four chrome fields go through `RenderService.render`/`resolveText`, which enforce TMPL-05's timeout and collection cap. Grep criteria assert `RenderEnginePort` is never imported by this service, so no bypass can exist. `boundBreachPropagates` asserts no partial snapshot is written on breach. |
| T-05-16 | Elevation of Privilege (SSTI) | template body reaching jmustache | mitigate | No new engine surface: the same `RenderService` → `RenderEnginePort` path Phase 4 shipped, with `TemplateScanner` marking unknown tokens and `RenderContextMapper` handing over plain Maps only. This plan adds a caller, not a capability. |
| T-05-17 | Repudiation | `generated_by` | mitigate | The actor is taken from `Principal.getName()` at the controller (Spring Security guarantees a principal on every `/api/**` path) and is `NOT NULL` in V5. No overload accepts a caller-supplied actor. |
| T-05-18 | Tampering (content-type confusion on logo download) | `GET .../logo` | mitigate | `Content-Type` comes from the stored, content-sniffed metadata (never from the filename), plus `X-Content-Type-Options: nosniff` and `Content-Disposition: inline` — copied verbatim from `TemplateController.downloadLogo`. |
| T-05-19 | Information Disclosure (cross-release document access) | all four endpoints | mitigate | Every endpoint is keyed on `releaseId` **and** `documentType`, and the repository queries filter on both, so a revision number from one release cannot address another's document. `/api/**` is `authenticated()` in `SecurityConfig`. |
| T-05-20 | Tampering (CSRF on the generate action) | `POST .../documents/{type}` | mitigate | Inherited unchanged: `CsrfFilter.DEFAULT_CSRF_MATCHER` is restored on top of `csrf.spa()` and the SPA echoes `X-XSRF-TOKEN` on every non-GET (Phase 1 decision). No new configuration. |
</threat_model>
