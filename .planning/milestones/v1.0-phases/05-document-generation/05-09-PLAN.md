<objective>
Complete DOC-02: make the grouping dimension a per-template setting, add `{{component}}` to the
item view-model, and surface both in the authoring UI.

Purpose: plan 05-07 made the component *data* available. This plan turns it into the grouping
dimension the reference customer document actually needs — `docs/templates/orchstro-release-notes.md`
calls the component-shaped section headings "the one thing this template cannot reproduce today".

**Backwards compatibility is the point of D-05-04.** `{{#groups}}`, `{{groupName}}` and the section
shape do not change. Only which field keys the grouping changes, and the default is `ISSUE_TYPE`, so
every Phase 4 template renders identically. Phase 4 shipped the group shape early precisely so this
change would be additive.

This is planned as one plan rather than three because the pieces are inseparable in practice:
`PlaceholderCatalogTest` is a reflection drift guard that fails the build unless the new `ItemView`
field and its catalog entry land in the same commit, and a persisted setting with no way to set it is
not a shippable increment.

Output: one enum, one view-model field, an assembler overload, a persisted template setting with its
API, and one toolbar control.
</objective>

|----------|-------------|
| SPA → `PUT /api/templates/{id}/content` | A new field on an existing authenticated write |
| Jira component text → view-model → renderers | External free text becoming a document heading |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-49 | Tampering (invalid enum reaching persistence) | `SaveTemplateContentRequest.groupingDimension` | mitigate | Bean-validated with `@Pattern(regexp = "ISSUE_TYPE|COMPONENT")` so an unknown value returns the existing `VALIDATION_FAILED` 400 before the service runs, and the V5 `CHECK` constraint is a second, independent gate at the database. A raw `valueOf` with no validation would surface as a 500. |
| T-05-50 | Tampering (stored XSS via a component name used as a heading) | `{{groupName}}` resolving to a component | mitigate | Group names flow through the same path as issue types today: React escapes them in the preview, flexmark `Text` nodes escape them server-side (D-04-05), and docx4j `Text` objects escape them in DOCX. No new sink — this changes which string fills an existing slot. |
| T-05-51 | Elevation of Privilege (expression surface) | `{{component}}` catalog token | mitigate | `component` is a plain `String` on `ItemView`, mapped into the context as a `Map` entry by `RenderContextMapper`. jmustache is handed Maps, never records, so no reflection or method invocation becomes reachable (TMPL-02). |
| T-05-52 | Tampering (silent grouping drift) | `assemble` call sites | mitigate | The one-argument `assemble` overload is removed rather than defaulted, so every call site must state its dimension explicitly and the compiler finds any that does not. A grep criterion asserts no one-argument overload survives. |
| T-05-53 | Repudiation (a document's grouping not matching its recorded template) | `DocumentGenerationService` | mitigate | Generation reads the dimension from the **same** `Template` instance whose name and body it copies onto the snapshot, so a snapshot's grouping is always consistent with its recorded provenance. |
</threat_model>
