<objective>
Deliver DOC-09: cross-release visibility of which paperwork is generated, stale or missing, plus the
frontend document API module the two screen plans (05-11, 05-12) consume.

Purpose: DOC-09 exists so outstanding release paperwork is visible "without opening each release one
at a time". D-05-08 puts it as three columns on the existing `/releases` table rather than a new
route — `03-CONTEXT.md` explicitly left room for this.

The one piece of real design here is **what "stale" means**. D-05-09 says the release changed after
the document was generated. `last_refreshed_at` covers refreshes, but a ticket **removal** leaves no
timestamp anywhere — `max(added_at)` cannot see it, so a removal would silently read as "Up to
date". Plan 05-03's V5 added `release.items_changed_at` for exactly this; this plan maps and stamps
it.

The frontend API module is bundled here rather than split out because it is the direct consumer of
this plan's endpoint and of plan 05-08's export URLs, and because a hook module with no caller is not
an increment. Splitting it would add an executor cycle and a merge for one file.

Output: a readiness state and service, one bulk endpoint, `items_changed_at` mapped and stamped, the
frontend document API module, the shared readiness pill, and the three `/releases` columns.
</objective>

**a) `client.ts` — add a binary sibling to `apiFetch`.** 05-PATTERNS.md flagged that export downloads

```typescript
export async function apiFetchBlob(path: string): Promise<Blob> {
  const response = await fetch(path, { credentials: 'same-origin' });
  if (!response.ok) {
    const problem = await response.json().catch(() => ({ status: response.status, reason: 'UNKNOWN' }));
    throw new ApiError({ ...problem, status: response.status, reason: problem.reason ?? 'UNKNOWN' });
  }
  return response.blob();
}
```
Exports are `GET`, so no CSRF header is needed. Reuse the existing `ApiError`/ProblemDetail parsing
so `messageForReason` works unchanged on a failed export.

Also export a download trigger, kept in `client.ts` beside it:
```typescript
export function triggerDownload(blob: Blob, filename: string): void {
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = filename;
  document.body.appendChild(a);
  a.click();
  a.remove();
  URL.revokeObjectURL(url);
}
```
`revokeObjectURL` is not optional: without it every export leaks a blob URL for the page's lifetime.
The filename passed in is the **client's own** composed name — the server's sanitised
`Content-Disposition` name is authoritative for a normal navigation download, but an
`URL.createObjectURL` download cannot read it, so compose a simple safe name client-side (release
name and version with the same `[A-Za-z0-9 ._-]` allowlist, falling back to `document`).
