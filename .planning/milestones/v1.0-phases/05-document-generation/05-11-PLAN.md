<objective>
Put document generation in front of the release manager: a Documents section on the release detail
screen with a Generate action per type, revision history, and export buttons.

Purpose: this is where DOC-01 becomes usable. Plans 05-03 through 05-10 built the whole backend and
the API module; this is the screen that drives them. It is also the landing target for the
`/releases` readiness links plan 05-10 shipped — those links point at `#documents` on this page, so
the anchor is a contract, not decoration.

already 553 lines with the ticket table, manual-item table and manual-item form, and this section has
its own four-state machine per row plus per-row mutation state. Inlining it would make one file
carry two unrelated state machines.

Output: one component, one integration point on the release route, and its tests.
</objective>

Export `DocumentsSection({ releaseId, releaseName, version }: {...})`. It renders one row per entry
in `DOCUMENT_TYPES` order inside:

```tsx
<section id="documents" className="mt-6 rounded border border-gray-200 bg-white p-4">
  <h3 className="text-base font-semibold text-gray-900">Documents</h3>
  ...
</section>
```

**Renders identically for OPEN and FROZEN releases** — unlike the Refresh/Freeze/Delete action row,
document generation is orthogonal to whether the item set can still change, and generating final
paperwork straight after freezing is the normal sequence. Do not gate any control on status.

Each row is `border-b border-gray-100 py-3 last:border-b-0` with four bands:

**Row 1** (`flex items-center justify-between`): the document type label as a Heading, and the
`<ReadinessPill>` for that type from `useDocumentReadiness()`.

**Row 2** (`text-sm text-gray-600`), by state, using this exact copy:
- `NO_ACTIVE_TEMPLATE` → `No active {DocumentType} template — create or activate one to generate this document.` plus a `Go to templates` link (`text-blue-600 underline`) to `/templates`.
- `NOT_GENERATED` → `This document hasn't been generated yet.`
- `STALE` → `Revision {n} of {n} · generated {date} by {actor}. The release has changed since this was generated.`
- `UP_TO_DATE` → `Revision {n} of {n} · generated {date} by {actor}.`

**Row 3 — actions**, by state:
- zero revisions, active template exists → only
  `<button className="rounded bg-blue-600 px-4 py-2 text-sm font-semibold text-white disabled:opacity-50">Generate {DocumentType}</button>`
- no active template → only the `Go to templates` link. **No generate control is rendered at all** —
  nothing to click that would work.
- one or more revisions → `View` (`text-blue-600 underline text-sm`, links to
  `/releases/$releaseId/documents/$documentType`) · `Export PDF` / `Export DOCX`
  (`border-gray-300 text-gray-700 text-sm px-3 py-1.5 rounded`) · `Regenerate {DocumentType}` —
  **blue (`bg-blue-600 text-white`) only while that row is `STALE`**, gray-bordered secondary
  otherwise. Amber marks the status, blue marks the available fix; the two never collide on one
  element.

**Regenerate opens no confirmation dialog.** Regenerating is additive (D-05-06 — nothing is ever
overwritten or pruned), so there is nothing destructive to confirm. Do not reuse `ConfirmDialog` here.

**Row 4** — only when revisions exist: a disclosure button mirroring the ticket-expand pattern:
```tsx
<button type="button" aria-expanded={open}
        aria-label={open ? 'Hide revision history' : 'Show revision history'}>
  {open ? '▾' : '▸'} Revision history ({n})
</button>
```
Collapsed by default. Expanded, it lists revisions **newest first** (matching the release library's
recency-first convention), each `text-gray-600 text-xs` reading `Revision {n}` plus `(latest)` or
`(superseded)`, the date and actor, and its own `View` / `Export PDF` / `Export DOCX` actions — so a
superseded revision's paperwork is reachable without opening the viewer (D-05-06: every revision
stays exportable).

**Pending states** (UI-SPEC Copywriting Contract):
- generating → the button label becomes `Generating…` with the existing border-spin glyph, the button
  disables, **and that row's View/Export controls disable for the same duration** so nothing acts on
  a revision mid-write. Other rows stay fully usable.
- exporting → the clicked button's label becomes `Exporting PDF…` / `Exporting DOCX…` with the spin
  glyph and only that button disables — each export is an independent on-demand render with no
  shared lock, so the sibling format and other revisions stay usable.
- export success → **no banner**. The file download is the success signal. Do not add a toast.

**Errors** — `role="alert" data-reason={reason}` with `messageForReason(problem)`, rendered directly
below the row it belongs to and **scoped per document type**: hold mutation state in a
`Record<DocumentType, ...>` or render one `<DocumentRow>` child per type with its own hooks. A
Release Notes generation failure must not appear under Runbook. Copy:
- generation → `text-red-600 text-sm`, `Couldn't generate {DocumentType} — {detail}. Try again.`
- export → `text-red-600 text-xs`, `Couldn't export the {PDF|DOCX} — {detail}. Try again.`
The button that triggered it stays the retry action; add no separate "Try again" button.

Use `green`, `amber` and `red` only where the UI-SPEC's reserved-for lists allow: the pill carries
green/amber, errors carry red, and **no destructive-styled control exists anywhere in this phase**.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SPA → document generate/export endpoints | User-initiated state change and binary downloads from an authenticated screen |
| server-supplied document metadata (template name, actor) → rendered DOM | Values that originate as untrusted template text or external identity data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-61 | Tampering (XSS via template name or actor in the row copy) | `DocumentsSection` row body text | mitigate | Every server value is rendered as a React text child, never through `dangerouslySetInnerHTML`, so React escapes it. This component renders no HTML from data at all — the one place this app injects HTML (`TemplatePreview`'s body region) is not touched here. |
| T-05-62 | Tampering (CSRF on generate) | `useGenerateDocument` | mitigate | Inherited unchanged: `apiFetch` echoes `XSRF-TOKEN` as `X-XSRF-TOKEN` on every non-GET and sends `credentials: 'same-origin'`. This plan adds a caller, not a transport. |
| T-05-63 | Tampering (acting on a revision mid-write) | generate pending state | mitigate | While a row's generate mutation is pending, that row's View and Export controls are disabled, so no request can address a revision number that is being written. Scoped per row so it does not block the other two document types. Asserted by `generatePendingDisablesThatRowsExportsOnly`. |
| T-05-64 | Repudiation / user confusion (destructive-looking regeneration) | Regenerate action | mitigate | Regeneration is append-only at the data layer (D-05-06), and the UI reflects that: no confirmation dialog, no destructive styling, and the revision history keeps every superseded revision visible and exportable. A confirm dialog here would misrepresent the operation as destructive. Asserted by `regenerateOpensNoDialogAndAppends`. |
| T-05-65 | Information Disclosure (a failure in one row leaking into another's context) | per-row error state | mitigate | Mutation and error state is held per document type, so a `NO_ACTIVE_TEMPLATE` or `EXPORT_FAILED` message renders only under the row that produced it. Asserted by `generationErrorIsScopedToItsOwnRow`. |
| T-05-66 | Denial of Service (repeat submission) | Generate / Export buttons | mitigate | Each button disables while its own mutation is pending, so a double-click cannot queue a second generation and create a spurious extra revision. |
| T-05-67 | Information Disclosure (error detail leakage) | `messageForReason` | accept | Error copy is chosen client-side from the machine-readable `reason` and the server's own `detail`, which plan 05-08 already restricts to fixed, generic strings with no internals. No stack trace or internal identifier can reach the DOM. |
</threat_model>
