## The Structural Guarantee Worth Recording

`D-05.2-02` required that release membership never reach Jira's JQL. Rather than forbidding it by
convention, the release scope is threaded as a **separate argument** to
`TicketSearchService.search(criteria, releaseId)` instead of becoming a field on `TicketSearchCriteria`.
`toJql()` therefore has no access to it — the constraint is enforced by the type system, not by a
comment someone could later ignore. Verified: `grep -c 'releaseId' TicketSearchCriteria.java` returns 0,
and the record is untouched by the phase.

## Incident During Execution

The frontend toolchain broke mid-phase and was repaired. A Vite dev server left running by phase 05.1's
human checkpoint held open handles inside `frontend/node_modules`; Maven's frontend profile runs
`npm ci`, which deletes and reinstalls that tree, and the delete failed partway with Windows EPERM
(-4048). This left `node_modules` at 21 entries with `react` and `vitest` missing, so `mvn clean test`
failed for reasons unrelated to any code change. Fixed by stopping the dev server and re-running
`npm ci` (121 packages restored); both suites and the full Maven build were re-verified green afterwards.

**Rule this establishes:** do not run a Vite dev server while a Maven build may run. The two contend for
`node_modules`, and the failure mode is a partially deleted dependency tree rather than a clean error.
