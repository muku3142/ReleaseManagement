<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> PUT/DELETE /api/templates/{id}/my-default | client-supplied path id; authenticated principal |
| server -> browser | per-requester myDefault flag |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.4-17 | Elevation of privilege | setting or clearing another user's default | mitigate | Both endpoints take no body and pass `principal.getName()` as the account; a slice test sends an `accountId` in the body and proves it is ignored. |
| T-05.4-18 | Information disclosure | reading another user's default | mitigate | `myDefault` is computed only from `myDefaultIds(principal.getName())`; there is no endpoint that accepts an account id. |
| T-05.4-19 | Tampering | cross-type default | mitigate | No document type is accepted from the client; the repository derives it from the template (D-05.4-04, plan 01 upsert). |
| T-05.4-20 | Tampering | unknown template id | mitigate | Repository upsert affecting 0 rows throws TemplateNotFoundException -> 404 TEMPLATE_NOT_FOUND; clear calls `get()` first. |
| T-05.4-21 | Tampering | CSRF on PUT/DELETE | mitigate | Same Spring Security CSRF + SameSite=Strict posture as every other template mutation; tests use `.with(csrf())`. |
| T-05.4-22 | Denial of service | N+1 on list | mitigate | One `myDefaultIds` call per response, asserted with `times(1)`. |
</threat_model>
