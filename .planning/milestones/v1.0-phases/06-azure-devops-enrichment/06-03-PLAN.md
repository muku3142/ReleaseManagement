<objective>
Make every Jira-backed release item able to hold its code links and status history: capture the numeric issue id,
`updated` time and status category from the existing search, add the V9 schema, carry `CodeLinks` on `ReleaseItem`,
and add the single persistence write path `saveEnrichment` with the lock and the document-fingerprint stamp rule.

Purpose: D-06-01 says enrichment is materialised per item and never fetched on read. This plan is the storage half;
06-05 fills it. Commits keep their author date and history keeps categories so Phase 8's set-based SQL works
(INSIGHT-03 data capture).

Output: `TicketDetail` + 3 components across all call sites, `V9__ado_enrichment.sql`, three child entities and
repositories, `ReleaseItem(ticket, addedAt, codeLinks)`, `saveEnrichment`, and persistence tests.
</objective>
