<objective>
Put promotion tracking on the release page: stepped-dot ladder with the current stage, a "Record promotion" dialog, the
promotion history list, and an in-page link to the existing document revision history.

Phase user story: **As a** release manager, **I want to** record each promotion of a frozen release through the environment ladder
and review its complete append-only history, **so that** I always know where every release sits and how it got there.

Purpose: after this plan the release manager can do the phase's core job in the browser (ROADMAP criteria 1-4). No UI-SPEC
exists (`--skip-ui`): copy existing Tailwind classes; no timeline component (DEPL-06 is v2).

API from 07-03 (`GET` and `POST /api/releases/{releaseId}/promotions`, POST returns 201 with the same shape):
```ts
export type PromotionOutcome = 'SUCCESS' | 'FAILED' | 'ROLLED_BACK' | 'VOIDED';
export type PromotionStage = { id: string; name: string; position: number; production: boolean; retired: boolean };
export type PromotionEntry = {
  id: string; stageId: string; stageName: string; outcome: PromotionOutcome;
  deployedAt: string; recordedAt: string; recordedBy: string; note: string | null;
  supersedesId: string | null; supersededById: string | null; correctionReason: string | null; effective: boolean;
};
export type PromotionHistory = { stages: PromotionStage[]; currentStageId: string | null; nextStageId: string | null; entries: PromotionEntry[] };
// POST body: { stageId, outcome: 'SUCCESS' | 'FAILED' | 'ROLLED_BACK', deployedAt?: ISO instant, note?: string }
```
Reason codes (409 unless noted): RELEASE_NOT_FROZEN, PROMOTION_STAGE_SKIPPED, PROMOTION_TARGET_RETIRED, PROMOTION_ROLLBACK_WITHOUT_SUCCESS,
PROMOTION_ALREADY_SUPERSEDED, PROMOTION_DEPLOYED_AT_INVALID (422), PROMOTION_OUTCOME_NOT_RECORDABLE (422), PROMOTION_NOT_FOUND (404),
STAGE_NOT_FOUND (404), STAGE_IN_USE, STAGE_NAME_DUPLICATE, PRODUCTION_STAGE_PROTECTED, LAST_ACTIVE_STAGE, STAGE_RETIRED, STAGE_ORDER_MISMATCH (422).
