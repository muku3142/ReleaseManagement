       ```bash
       #!/bin/bash
       set -euo pipefail
       : "${RAG_DB_PASSWORD:?}"
       psql -v ON_ERROR_STOP=1 -v rag_pw="$RAG_DB_PASSWORD" --username "$POSTGRES_USER" --dbname postgres <<'EOSQL'
       SELECT 'CREATE ROLE rag LOGIN PASSWORD ' || quote_literal(:'rag_pw') WHERE NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'rag') \gexec
       SELECT 'CREATE DATABASE ragdb OWNER rag' WHERE NOT EXISTS (SELECT FROM pg_database WHERE datname = 'ragdb') \gexec
       REVOKE CONNECT ON DATABASE ragdb FROM PUBLIC;
       EOSQL
       psql -v ON_ERROR_STOP=1 --username "$POSTGRES_USER" --dbname ragdb -c 'CREATE EXTENSION IF NOT EXISTS vector'
       psql -v ON_ERROR_STOP=1 --username "$POSTGRES_USER" --dbname postgres -c "REVOKE CONNECT ON DATABASE \"$POSTGRES_DB\" FROM PUBLIC"
       ```
       The superuser creates the extension here because `vector` is not a trusted extension, so `rag` cannot create it itself

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rag role -> releasemgmt database | The new low-privilege role must not reach v1 data |
| compose env -> init script | The password comes from env and is passed to psql as a variable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Information disclosure | rag role reading releasemgmt | mitigate | `REVOKE CONNECT ON DATABASE "$POSTGRES_DB" FROM PUBLIC`; probe (c) proves `permission denied for database` |
| T-09-02 | Elevation of privilege | rag role | mitigate | `rag` is created LOGIN only (no SUPERUSER/CREATEDB/CREATEROLE). The extension is created by the superuser, so `rag` never needs elevated rights |
| T-09-03 | Information disclosure | releasemgmt superuser reading ragdb | accept | One-way isolation, recorded honestly (research correction to D-09-13). The real fix (own server) is deferred |
| T-09-04 | Tampering | SQL injection through RAG_DB_PASSWORD | mitigate | The password is bound with `psql -v` and `quote_literal(:'rag_pw')`, never interpolated into SQL text |
| T-09-05 | Information disclosure | Postgres port exposure | mitigate | Keep `127.0.0.1:5432:5432` (loopback only, D-09-17) |
</threat_model>
