    1. `VectorLiteral` (package-private final class, `static String of(float[] v)`): builds `"[v0,v1,...]"` with a `StringBuilder`,
       commas and no spaces, using `Float.toString`. Used by both adapters with `CAST(:x AS vector)` (no pgvector-java).
    2. `IndexQueueRepositoryAdapter implements IndexQueue` (`@Component`; each method `@Transactional`, one short transaction each;
       the Ollama call happens between claim and complete in the worker, never inside these methods):
       - claim:
         ```sql
         WITH due AS (
             SELECT id FROM document
             WHERE status = 'PENDING' AND (lease_until IS NULL OR lease_until < now())
             ORDER BY updated_at
             LIMIT :batchSize
             FOR UPDATE SKIP LOCKED)
         UPDATE document d SET lease_until = now() + make_interval(secs => :leaseSeconds)
         FROM due, collection c
         WHERE d.id = due.id AND c.id = d.collection_id
         RETURNING d.id, d.collection_id, c.embedding_model, d.title, d.body, d.content_hash
         ```
         bind `leaseSeconds` as `lease.toSeconds()` (double or long).
       - release: `UPDATE document SET lease_until = NULL WHERE id IN (:ids)` (JdbcClient expands a `Collection` parameter); no-op on empty.
       - complete: `UPDATE document SET status = 'INDEXED', indexed_at = now(), lease_until = NULL, status_reason = NULL WHERE id = :id AND content_hash = :hash`;
         if 0 rows return false (stale or deleted; D-09-11) and insert nothing. Otherwise `DELETE FROM chunk WHERE document_id = :id`,
         then insert each chunk: `INSERT INTO chunk (document_id, collection_id, ordinal, content, embedding, embedding_model) SELECT :id, collection_id, :ordinal, :content, CAST(:embedding AS vector), :model FROM document WHERE id = :id`;
         return true. All in the same transaction.
       - fail: `UPDATE document SET status = 'FAILED', status_reason = :reason, lease_until = NULL WHERE id = :id AND content_hash = :hash`.
    3. `IndexQueuePersistenceIT` (pgvector container; `@BeforeEach` clean; seed client/collection/documents via SQL). Tests:
       - claim returns only PENDING docs with null or expired lease, sets lease_until in the future, includes the collection's embedding_model
       - a second claim immediately after returns nothing for the same docs (lease held)
       - concurrency: two threads each calling claim(10, PT10M) on 10 PENDING docs receive disjoint id sets whose union is 10 (SKIP LOCKED)
       - an expired lease (set lease_until = now() - interval '1 second' via SQL) is claimable again
       - release clears lease_until and leaves status PENDING
       - complete with the claimed hash -> true, status INDEXED, indexed_at set, exactly N chunk rows with embedding_model set; a second complete replaces (not appends) chunks
       - complete after the document's content_hash was changed via SQL -> false, status stays PENDING, no chunks inserted (stale discard)
       - complete after the document was deleted -> false, no chunk rows, no exception
       - fail with the claimed hash -> FAILED with reason; fail with a stale hash -> no change

    Base SQL:
    ```sql
    SELECT d.external_id, d.title, d.url, d.metadata, c.ordinal, c.content,
           1 - (c.embedding <=> CAST(:q AS vector)) AS score
    FROM chunk c JOIN document d ON d.id = c.document_id
    WHERE c.collection_id = :collectionId AND c.embedding_model = :model
    ```
    For clause i of the filter append ` AND (d.metadata @> CAST(:f{i}_0 AS jsonb) OR d.metadata @> CAST(:f{i}_1 AS jsonb) ...)`,
    one parameter per value; each parameter value is `objectMapper.writeValueAsString(Map.of(clause.key(), value))`, so the key
    and value are JSON-encoded by Jackson and bound, never concatenated into SQL (only the generated names `f0_0` etc. are). Then
    ` ORDER BY c.embedding <=> CAST(:q AS vector) LIMIT :k`. `:q` = `VectorLiteral.of(queryVector)`. Map rows to `SearchHit`
    (metadata parsed back to `Map<String,Object>`). `@>` is type-sensitive (string "3" does not match number 3), which is the
    intended D-09-07 semantics; document that in a one-line comment. Chunk-level hits; a document may appear more than once
    (Open Question 3 adopted). Documents in any status are searchable if they have chunks (serve-old-until-new, RESEARCH A6).
    `ChunkSearchPersistenceIT` (seed via SQL; vectors are unit vectors built in the test, e.g. e_0, e_1, and a mix normalised):
    - query e_0 over chunks e_0, mix(e_0,e_1), e_1 -> order [e_0, mix, e_1]; score of e_0 hit ~= 1.0
    - k=2 returns 2 hits
    - equality filter `release_id="R1"` excludes docs with `release_id="R2"` and docs without the key
    - in-list `project_key in ["A","B"]` returns A and B docs, not C; equality + in-list combined are ANDed
    - number filter `count=3` matches number 3 but not string "3"
    - chunks of another collection with an identical vector never appear
    - chunks whose `embedding_model` differs from the given model never appear
    - a filter key containing a quote, e.g. `a"b`, is handled safely (returns no rows, no SQL error) - proves binding
    - a deleted document (DELETE FROM document) has no hits (cascade)
