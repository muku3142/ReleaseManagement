    `assertReady()`: `healthClient.post().uri(baseUrl + "/api/show").contentType(APPLICATION_JSON).body(Map.of("model", model))
    .retrieve().body(ShowResponse.class)`; null or no `"completion"` in capabilities -> `ModelNotAvailableException(model)`.
    Catch `HttpClientErrorException.NotFound` -> `ModelNotAvailableException(model)`; any other `RestClientException` ->
    `OllamaUnavailableException("Chat backend unreachable", e)`. Never log or forward the show body (it embeds a licence, ~50 KB).

    `stream(...)`: per AI-SPEC section 3 item 3, with the RESEARCH corrections:
    ```java
    try {
        return streamClient.post().uri(baseUrl + "/api/chat").contentType(MediaType.APPLICATION_JSON).body(request)
            .exchange((req, response) -> {
                int status = response.getStatusCode().value();
                if (status != 200) { throw statusFailure(status, response); }
                InputStream in = response.getBody();
                cancel.onCancel(() -> closeQuietly(in));   // runs on the canceller's thread; idempotent
                return readNdjson(in, onToken, cancel);
            });
    } catch (ResourceAccessException e) {
        if (cancel.isCancelled()) { return Completion.cancelled(cancel.reason()); }
        if (hasCause(e, HttpTimeoutException.class)) { throw new GenerationFailedException("Generation exceeded the stream timeout", e); }
        throw new OllamaUnavailableException("Chat backend unreachable", e);
    }
    ```
    `statusFailure`: 404 -> `ModelNotAvailableException(model)`; 400 -> read at most 1024 bytes of the body, if it contains
    "does not support chat" -> `ModelNotAvailableException(model)`, else `GenerationFailedException("Chat request rejected with 400")`;
    5xx -> `OllamaUnavailableException("Chat backend error " + status)`; anything else -> `GenerationFailedException("Chat call failed with " + status)`.
    The body is never put into a message or log.

    `readNdjson`: `BufferedReader` over UTF-8; skip blank lines; parse each line into `ChatChunk` (catch `JacksonException` ->
    `GenerationFailedException("Malformed stream line " + lineNumber)` unless cancelled); `error != null` ->
    `GenerationFailedException("Chat backend reported a stream error")`; non-empty `message.content` -> `onToken.accept(...)`;
    `done` -> `new Completion(doneReason, promptEvalCount, evalCount, nsToMs(loadDuration), nsToMs(totalDuration), null)`.
    Catch `IOException` -> if cancelled return `Completion.cancelled(cancel.reason())`, else `GenerationFailedException("Chat stream read failed", e)`.
    AFTER the loop and BEFORE throwing "Chat stream ended without a done message", check `if (cancel.isCancelled()) return
    Completion.cancelled(cancel.reason());` (closing the stream usually yields EOF, not IOException - RESEARCH Pitfall 2).
    Pre-header cancellation uses RESEARCH Pattern 3 option 1 (no thread interrupt): the read-timeout backstop bounds the
    pre-header wait, and `onCancel` runs immediately once headers arrive if already cancelled.

    No log statements are needed here; if any are added they log class names and counts only.
    Write OllamaChatAdapterTest covering the behavior block, with a `SECRET_TEXT` constant in every stubbed body.
