    - first sync of release R with 2 tickets + 1 doc -> 3 puts; recordedIds(R) has the 3 refs
    - after removing ticket PAY-2 from the fixture -> next sync puts 2 and deletes ticket:R:PAY-2 (and codelinks:R:PAY-2 if recorded); recorded set shrinks
    - delete throwing RagServiceException(503) -> ref stays recorded; next sync deletes it again; a 404 never reaches the syncer (adapter maps it to success)
    - put throwing on one document -> remaining documents still pushed; sync returns normally; the id is still recorded (so a later removal deletes it)
    - release no longer found -> every recorded ref deleted and the release entry dropped when all deletes succeeded
    - log lines captured (Logback ListAppender) contain collection, id and status but not the document text or title
    - two threads calling sync(R) concurrently never interleave put sequences (lock; assert with a port fake that detects overlap)
  </behavior>
  <action>
    `@Service @ConditionalOnProperty(prefix = "app.assistant", name = "enabled", havingValue = "true") public class IndexSyncer`,
    constructor `(ReleaseRepository releases, DocumentSnapshotRepository snapshots, RagIndexPort index)`. Fields:
    `private final ReentrantLock lock = new ReentrantLock();`, `private final Map<UUID, Set<DocRef>> recorded = new ConcurrentHashMap<>();`.
    `public void sync(UUID releaseId)`: lock; `findById`; if empty -> delete all recorded; else latest = for each
    `TemplateDocumentType.values()` `snapshots.findLatest(...)`; desired = `IndexDocumentMapper.map(release, latest)`;
    recorded(R) := recorded(R) ∪ desired refs; put each desired (catch RuntimeException per document -> `log.warn("rag index put failed collection={} id={} status={}", ...)`);
    for each recorded ref not desired: delete, remove from recorded on success, warn on failure; unlock in finally.
    The read happens inside the lock (Pitfall 2). `public void ensureCollections()` -> `ensureCollection` for each
    `IndexCollection` (catch, log `ERROR` once per call for status 409 model conflict, `WARN` otherwise; never throw).
    `public Set<UUID> recordedReleaseIds()` returns a copy. Not `@Transactional` (slow network work must not hold a DB
    connection; each repository read is its own short read). No content-hash cache (healing, D-12-12).
