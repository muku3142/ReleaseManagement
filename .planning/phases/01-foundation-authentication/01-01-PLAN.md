**`V1__init_schema.sql`** — copy RESEARCH.md's baseline verbatim (both tables; `jira_credential` is created now even though plan 04 is what maps it, so there is exactly one baseline migration for the phase):
```sql
CREATE TABLE jira_site_config (
    id          SMALLINT PRIMARY KEY DEFAULT 1 CHECK (id = 1),
    base_url    VARCHAR(255) NOT NULL,
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by  VARCHAR(255) NOT NULL
);

CREATE TABLE jira_credential (
    jira_account_id  VARCHAR(255) PRIMARY KEY,
    jira_email       VARCHAR(255) NOT NULL,
    encrypted_token  TEXT NOT NULL,
    key_version      SMALLINT NOT NULL,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
```
Add no `refresh_token`, `session` or `token_denylist` table — refresh tokens are stateless JWTs (D-05, D-09) and a table here would silently reintroduce the server-side session state those decisions reject.
