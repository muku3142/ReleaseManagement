### The five things Phase 2 must not get wrong

1. **`/rest/api/3/search/jql` only.** Legacy `/rest/api/*/search` returns **410 Gone**.
   Terminate the paging loop on **absence of `nextPageToken`**, NOT on `isLast` — community
   reports say `isLast` never flips true here. There is **no `total`** in the response; a
   separate `POST .../approximate-count` gives an advisory number only.
2. **A hard page-count safety ceiling is mandatory** so a token-chaining bug fails loudly
   rather than looping forever. Silent truncation (JIRA-03) and infinite looping are mirror
   failures; both must be designed against. This breach needs its own reason code —
   `RESULT_SET_TOO_LARGE` — because generic `JIRA_ERROR` copy would send the user looking in
   the wrong place. **All six other JIRA-06 reason codes already exist verbatim from Phase 1.**
3. **No server pager exists or can exist.** Cursors forbid page-jumping. Backend pages to
   exhaustion and returns the complete set once; the frontend does client-side checkbox
   selection over the loaded array.
4. **Every Jira read goes through `JiraAccessContextService.currentContext()`.** This is where
   AUTH-02 stops being vacuous. There is deliberately no overload taking an accountId.
5. **`dev-status` needs Jira's numeric issue id**, obtained via `GET /rest/api/3/issue/{key}`
   first — not the issue key, even though every other v3 endpoint accepts either.

  not a code problem — `javac` compiles all sources cleanly.
- **The GSD CLI is `gsd-tools`, not `gsd-sdk`.** Run as
  `node "C:/Users/ucs/.claude/get-shit-done/bin/gsd-tools.cjs" <cmd>`. Workflow docs say
  `gsd-sdk query group.name` → translate to `gsd-tools group-name`.

  Verify with `git diff` and edit manually if needed.
- **`src/test/resources/application.yml` SHADOWS main's** rather than merging. New config
  properties must go in both or full-context ITs fail on unresolved placeholders.
- **Worktree merges produce CRLF files.** This silently broke the code-review workflow's
  SUMMARY parser (`/^---\n/` fails on `\r\n`), which dropped 3 of 7 plans — 29 files including
  the crypto converter — while still reporting success. Expect it for any phase using
  worktree parallelism.
- **Maven incremental compilation hides broken tests.** If main sources change but test sources
  do not, `mvn test-compile` can pass while tests reference deleted methods. Use `mvn clean`
  when changing public APIs.
- **Docker:** `docker compose -f compose.app.yaml up --build -d` — `up -d` alone does NOT
  rebuild. Compose interpolates required env vars even for `build`, so `.env` must exist.
  `--force-recreate` is required for `.env` changes to reach a running container.
  `postgres:18` mounts at `/var/lib/postgresql`, **not** `/data`.
- **Boot's docker-compose integration fails** on this machine (Docker CLI/daemon API skew).
  For a local run: `docker compose up -d` then
  `-Dspring-boot.run.arguments=--spring.docker.compose.enabled=false`.
- **Sign-in:** with `RM_PROFILES=local,stub-jira` use `dev@example.com` / `valid-token`. With
  `RM_PROFILES=local` (current) use real Jira credentials.

## Decisions worth not relitigating

- **This tool sits beside Jira, not over it.** Jira is a read-only ticket source; this app is
  the system of record for release state. Dashboards must answer what Jira **cannot** —
  documentation status, ladder position, promotion history. Velocity/cycle-time/sprint-scope
  charts were scoped and **dropped**: Jira ships them, and rebuilding them would cost the Agile
  API, paginated `/changelog` and the story-point custom field. Recorded in PROJECT.md
  out-of-scope so it does not recur.
- **CSRF depends on `SameSite=Strict`.** `oauth2ResourceServer()` unconditionally CSRF-exempts
  requests with a resolvable bearer token, and ours is cookie-borne. `SameSite=Strict` is the
  actual control. **If anyone relaxes it, the CSRF exposure becomes real** — re-review before
  shipping that change.
- **v1 is 47 requirements**, up from 40 on 2026-07-31. Added: document chrome (TMPL-08/09,
  DOC-08), manual release items (REL-08), cross-release deploy history (AUDIT-04),
  drag-and-drop (UX-01), documentation readiness (DOC-09).
