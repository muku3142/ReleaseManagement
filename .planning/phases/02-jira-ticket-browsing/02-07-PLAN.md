export type Ticket = { key; summary; issueType; status; resolution; assignee; reporter;

<decisions>

**D-PLAN-07-A — The detail panel renders flattened text in a `whitespace-pre-wrap` block, not
parsed Markdown.**
The backend already produced human-readable text with newlines. Adding a Markdown renderer to
the frontend would be a new dependency to re-parse something that is deliberately no longer a
structured document, and it would make the browse view and Phase 5's generated documents
diverge in how the same string is interpreted. `whitespace-pre-wrap` preserves the flattener's
line structure with zero dependencies and zero HTML injection surface.

**D-PLAN-07-B — Choosing the JQL path clears the picker selection for that search.**
UI-SPEC: "Choosing to use the JQL textarea and clicking Load tickets ignores/clears the project
and fixVersion selects for that search". The backend rejects a body carrying both modes with
`VALIDATION_FAILED` (plan 05), so the UI must send exactly one — the discriminated union in
`TicketSearchCriteria` makes that structural rather than a convention.

**D-PLAN-07-C — Only one row is expanded at a time.**
A single `expandedKey: string | null` rather than a set. Nothing in UI-SPEC asks for multiple
simultaneous panels, and one open panel keeps the table scannable, which is the reason the row
layout was chosen over cards in the first place.

**D-PLAN-07-D — Comment truncation is shown, not hidden.**
Jira embeds only the first page of comments in a search result. Plan 03 carries `commentTotal`
precisely so this screen can say so. Displaying 20 of 60 comments as if that were all of them
would be the same class of silent truncation JIRA-03 exists to prevent.

</decisions>
