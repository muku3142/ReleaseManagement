```sql
-- The Release aggregate: the first entity this system owns rather than reads from Jira.
-- Ticket items store a full materialised copy of the Jira ticket (D-03-06) so that opening a
-- release never issues a Jira call, and so a frozen release keeps the field values it had at
-- freeze rather than whatever Jira says today.

CREATE TABLE release (
    id                 UUID PRIMARY KEY,
    name               VARCHAR(200)  NOT NULL,
    version            VARCHAR(100)  NOT NULL,
    status             VARCHAR(16)   NOT NULL CHECK (status IN ('OPEN', 'FROZEN')),
    jira_project_key   VARCHAR(64),
    created_at         TIMESTAMPTZ   NOT NULL DEFAULT now(),
    created_by         VARCHAR(255)  NOT NULL,
    frozen_at          TIMESTAMPTZ,
    frozen_by          VARCHAR(255),
    last_refreshed_at  TIMESTAMPTZ,
    CONSTRAINT release_name_version_unique UNIQUE (name, version)
);

CREATE TABLE release_ticket_item (
    id             UUID PRIMARY KEY,
    release_id     UUID          NOT NULL REFERENCES release (id) ON DELETE CASCADE,
    ticket_key     VARCHAR(64)   NOT NULL,
    summary        VARCHAR(1000) NOT NULL,
    issue_type     VARCHAR(100)  NOT NULL,
    status         VARCHAR(100)  NOT NULL,
    resolution     VARCHAR(100),
    assignee       VARCHAR(255),
    reporter       VARCHAR(255),
    fix_versions   TEXT          NOT NULL,
    description    TEXT          NOT NULL,
    comments       TEXT          NOT NULL,
    comment_total  INTEGER       NOT NULL,
    added_at       TIMESTAMPTZ   NOT NULL DEFAULT now(),
    CONSTRAINT release_ticket_item_key_unique UNIQUE (release_id, ticket_key)
);

CREATE TABLE release_manual_item (
    id           UUID         PRIMARY KEY,
    release_id   UUID         NOT NULL REFERENCES release (id) ON DELETE CASCADE,
    title        VARCHAR(200) NOT NULL,
    description  TEXT         NOT NULL,
    category     VARCHAR(32)  NOT NULL
                 CHECK (category IN ('CONFIG_CHANGE', 'DATABASE_SCRIPT', 'INFRASTRUCTURE', 'OTHER')),
    added_at     TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE INDEX release_manual_item_release_id_idx ON release_manual_item (release_id);
```

Notes that are decisions, not suggestions:
- `RELEASE` is a non-reserved keyword in PostgreSQL, so `release` is a legal unquoted table name.
  Do not rename the table.
- `fix_versions` and `comments` are `TEXT` holding a JSON array, written through the
  `JsonStringListConverter` built in task 3. They are deliberately NOT `jsonb`: nothing in this
  phase or Phase 5 queries inside those arrays, and binding a Java `String` to a `jsonb` column
  through the Postgres JDBC driver fails with "column is of type jsonb but expression is of type
  character varying" unless the connection is reconfigured globally. If a later phase genuinely
  needs JSON operators, `ALTER TABLE release_ticket_item ALTER COLUMN comments TYPE jsonb USING
  comments::jsonb` is a purely additive migration.
- `description` is `TEXT NOT NULL` holding the already-ADF-flattened plain text produced in
  Phase 2 — it is a plain string, not JSON.
- No `position` column and no ordering column of any kind (D-03-04). No sprint column and no
  sprint foreign key (D-03-09). No `application` table and no foreign key on `jira_project_key`
  (D-03-05) — it is advisory and unenforced.
- Only `release_manual_item` gets an explicit `release_id` index; `release_ticket_item` already
  has one as the leading column of `release_ticket_item_key_unique`.
- No new configuration property is introduced by this plan, so the
  `src/test/resources/application.yml` shadowing trap does not apply here. Do not add anything to
  either `application.yml`.

**`JsonStringListConverter.java`** in package
`com.evision.releasemgmt.adapters.persistence.converter`. Boot 4.1's managed Jackson is
**Jackson 3**: the `ObjectMapper` type is `tools.jackson.databind.ObjectMapper` and
`TypeReference` is `tools.jackson.core.type.TypeReference`.
`com.fasterxml.jackson.databind.ObjectMapper` does not resolve on this classpath. Jackson 3's
exceptions are unchecked (`tools.jackson.core.JacksonException extends RuntimeException`), so no
checked-exception handling is needed; if the compiler demands one, wrap it in
`IllegalStateException` to match `EncryptedTokenConverter`'s single-exception-type contract.

```java
@Component
@Converter
public class JsonStringListConverter implements AttributeConverter<List<String>, String> {

    private static final TypeReference<List<String>> LIST_OF_STRING = new TypeReference<>() { };

    private final ObjectMapper objectMapper;

    public JsonStringListConverter(ObjectMapper objectMapper) {
        this.objectMapper = objectMapper;
    }

    @Override
    public String convertToDatabaseColumn(List<String> value) {
        return objectMapper.writeValueAsString(value == null ? List.of() : value);
    }

    @Override
    public List<String> convertToEntityAttribute(String stored) {
        if (stored == null || stored.isBlank()) {
            return List.of();
        }
        return objectMapper.readValue(stored, LIST_OF_STRING);
    }
}
```
Both columns are `NOT NULL`, so a null attribute is written as `[]` rather than as SQL NULL — the
converter never returns null in either direction.
