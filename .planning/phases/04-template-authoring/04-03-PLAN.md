**Port.** Create `src/main/java/com/evision/releasemgmt/ports/RenderEnginePort.java`:
```java
package com.evision.releasemgmt.ports;

import java.util.Map;

public interface RenderEnginePort {

    /**
     * Resolves the Mustache placeholders in {@code source} against {@code context}, then parses the
     * resulting Markdown and renders it to HTML.
     *
     * <p>The context is plain data only - String, Boolean, List and Map. Passing a domain record or
     * a JPA entity here would hand the engine a reflection surface and defeat TMPL-02.
     *
     * <p>Raw HTML in {@code source} or in any interpolated value is escaped, never emitted as
     * markup (D-04-05).
     *
     * @throws com.evision.releasemgmt.domain.template.TemplateMalformedException
     *         when the engine rejects the source
     */
    String render(String source, Map<String, Object> context);
}
```

Put this comment above the class — it is the reason the mapper exists:
```java
// The engine is handed Maps, not the view records themselves. jmustache resolves a POJO property by
// reflecting for a field or an accessor; giving it a record would put method invocation back on the
// table, which is exactly what TMPL-02 forbids. A Map has one lookup path and no reflection.
```

**`application/RenderService.java`** — `@Service`, constructor-injecting `RenderEnginePort` plus
`@Value("${app.template.render.timeout}") Duration timeout` and
`@Value("${app.template.render.max-collection-size}") int maxCollectionSize`. It owns one

(`spring.threads.virtual.enabled: true` is already set in `application.yml`).

`public RenderResult render(String source, ReleaseView view, String field)` does, in order:

1. `ScanResult scan = scanner.scan(source, field);` — `TemplateScanner` is a plain domain class, so
   instantiate it as a `private static final TemplateScanner SCANNER = new TemplateScanner();`
   rather than injecting a bean. A `TemplateMalformedException` propagates untouched.
2. `enforceCollectionCap(view);` — throw `RenderBoundExceededException` if any of these exceeds
   `maxCollectionSize`: `view.items().size()`, `view.groups().size()`, any `group.items().size()`,
   any `item.comments().size()`, any `item.commits().size()`, any `item.pullRequests().size()`.
   Note the comment: unlike `AdfFlattener`, which truncates and appends `[content truncated]`, this
   throws — D-04-11 states that breaching *either* bound "surfaces as a `ProblemDetail` with a
   machine-readable `reason` ... not a generic 500", and a silently truncated release document is
   worse than a refused one.
3. `String safeSource = markUnknownTokens(source, scan.unknownTokens());` — see below.
4. `Map<String, Object> context = RenderContextMapper.toContext(view);`
5. Submit `() -> engine.render(safeSource, context)` to the executor and
   `future.get(timeout.toMillis(), TimeUnit.MILLISECONDS)`. On `TimeoutException`:
   `future.cancel(true); throw new RenderBoundExceededException();`. On `ExecutionException`,
   unwrap and rethrow the cause if it is a `RuntimeException`. Add this honest comment:
   ```java
   // cancel(true) interrupts the carrier thread but jmustache does not poll for interruption, so a
   // pathological render may keep running until it finishes. The collection cap above is what
   // actually bounds the work; the timeout bounds how long a caller waits for it.
   ```
6. `return new RenderResult(html, scan.unknownTokens());`

`markUnknownTokens(String source, List<String> unknown)` implements D-04-08. For every unknown token
`t`, replace, in a single left-to-right pass over the source:
- `{{t}}` (allowing surrounding spaces inside the braces) → the literal text `[[unknown: t]]`
- `{{#t}}` and `{{^t}}` → the literal text `[[unknown: t]]`
- the matching `{{/t}}` → the empty string

so the marker appears where the tag was and any enclosed content still renders inline. Comment why
this is done here rather than through a jmustache missing-key hook:
```java
// D-04-08 wants a conspicuous marker naming the token, not a blank. Producing it here - from the
// scanner's own list, before the source ever reaches the engine - means the guarantee is asserted by
// this codebase rather than resting on a library's missing-key behaviour, which is precisely the
// distinction D-04-06 draws for the rest of the subset.
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| template source → render engine | The single most dangerous boundary in this project: untrusted template text is compiled and executed by a templating library |
| Jira ticket text → rendered document | Ticket summaries, descriptions and comments are third-party content interpolated into HTML |
| render call → server resources | An arbitrarily complex template competing for CPU and memory on a single-jar deployment |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-12 | Elevation of Privilege | Server-side template injection through the template body | mitigate | jmustache is logic-less by design (no expression language to sandbox), `TemplateScanner` rejects every construct outside D-04-06's subset before compilation, and `RenderContextMapper` hands the engine only `Map`/`List`/`String`/`Boolean` so no reflective property or method path exists at all — asserted by `RenderServiceTest`'s leaf-type walk |
| T-04-13 | Elevation of Privilege | Stored XSS through `<script>` typed into a template body or arriving in a ticket summary | mitigate | flexmark parses with raw HTML disabled and the HTML renderer escapes it, so `<` can never become a tag; `MustacheFlexmarkRenderAdapterTest` asserts both the typed and the interpolated case, plus zero `HtmlBlock`/`HtmlInline` nodes in the AST so Phase 5's PDF/DOCX walk inherits the same guarantee |
| T-04-14 | Information Disclosure | A template reaching a file on disk through a partial | mitigate | Partials are rejected by the scanner (T-04-01) and no `Mustache.TemplateLoader` is ever registered on the compiler, so there is no loader to abuse |
| T-04-15 | Denial of Service | A template that renders forever, or over a release with hundreds of thousands of rows | mitigate | `RenderService` enforces `app.template.render.timeout` (PT2S) with a `Future.get(timeout)` and `app.template.render.max-collection-size` (500) as a pre-flight check on every collection in the context; `RenderServiceTest` trips both |
| T-04-16 | Tampering | A future caller (Phase 5) rendering without bounds | mitigate | `RenderEnginePort` is the only way to reach the engine and the ArchUnit rule added in Task 3 forbids importing `com.samskivert`/`com.vladsch` outside `adapters.render`; `RenderService` is the only injected caller of the port |
| T-04-17 | Spoofing | A rendered document silently omitting a mistyped field, misrepresenting the release | mitigate | Unknown tokens render as `[[unknown: token]]` (D-04-08) rather than blanking, in the preview and in every Phase 5 document |
