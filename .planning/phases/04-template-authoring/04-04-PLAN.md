<objective>
Put the template lifecycle and the render pipeline behind REST: `TemplateService`,
`TemplateController`, the request/response DTOs, the new `ProblemDetail` reason codes, and the two
read-only endpoints the authoring screen needs (the placeholder catalog and a release's view-model).

TMPL-06's "preview against a real release's actual data" and TMPL-08's chrome fields all become
reachable from a browser here. This plan also resolves UI-SPEC planning input #1 (new reason codes)
and #3 (a document type with zero active templates).

Output: one service, one controller, thirteen DTO records, an extended `GlobalExceptionHandler`, and
two test classes.

Behaviour notes, all concrete:

- `create` builds `Template.create(name.trim(), documentType, actor, Instant.now())` and delegates.
  New templates are **never auto-activated**, including when the type currently has none — the
  release manager marks one active explicitly, and UI-SPEC's zero-active state is a supported state
  (D-04-13, UI-SPEC planning input #3). Add that as a one-line comment so nobody "fixes" it later.
- `rename` loads, copies the record with the new trimmed name and `updatedAt`/`updatedBy`, delegates
  to `repository.update`. It runs no validation render — the name is not a template.
- `saveContent` is the TMPL-04 path:
  ```java
  Template existing = get(id);
  ReleaseView sample = SampleReleaseView.instance();
  List<String> warnings = new ArrayList<>();
  collect(warnings, body, sample, "Body");
  collect(warnings, chrome.coverTitle(), sample, "Cover title");
  collect(warnings, chrome.coverSubtitle(), sample, "Cover subtitle");
  collect(warnings, chrome.headerText(), sample, "Header text");
  collect(warnings, chrome.footerText(), sample, "Footer text");
  ```
  where `collect` skips null/blank sources, otherwise calls
  `renderService.render(source, sample, field)` and adds `token + " — " + field` for every unknown
  token. `TemplateMalformedException` and `RenderBoundExceededException` propagate untouched — they
  block the save (UI-SPEC state 4). Then persist via `repository.update` with the new body, chrome,
  `warnings`, `updatedAt = Instant.now()` and `updatedBy = actor`.
  Use the em-dash separator `" — "` exactly: the SPA renders the string verbatim in the
  "Show details" disclosure and UI-SPEC's example reads ``ticket.compnent — body``.
  Comment the deliberate deviation:
  ```java
  // D-04-07: unknown placeholders warn, they do not block. This is a deliberate, recorded deviation
  // from TMPL-04's "reports unknown placeholders as errors" - the requirement's actual intent is
  // preserved by D-04-08's [[unknown: token]] marker, which makes the defect loud at every render
  // instead of only at save time.
  ```
- `activate` delegates to `repository.setActive(id)`. It touches no other field, so `updatedBy` is
  not changed — activation is not an edit of the template's content. (`Principal` is still required
  at the controller so the audit story is uniform; record it in the summary if you disagree.)
- `duplicate` loads the source, then finds a free name: start from `name + " copy"`, and while
  `repository.findByDocumentType(type)` already contains that name, try `name + " copy " + n` for
  `n = 2, 3, …` up to 50, then give up and let `TemplateDuplicateException` surface. The copy carries

}

@ExceptionHandler(TemplateDuplicateException.class)
public ProblemDetail handleTemplateDuplicate(TemplateDuplicateException ex) {
    return problem(HttpStatus.CONFLICT, "Duplicate template name",
            "A template with this name already exists for this document type. Choose a different name.",
            "TEMPLATE_DUPLICATE");
}

// The one handler in this file whose detail is dynamic: the SPA renders it verbatim after
// "Template not saved — ", so it must name the specific defect and, for a chrome field, the field.
@ExceptionHandler(TemplateMalformedException.class)
public ProblemDetail handleTemplateMalformed(TemplateMalformedException ex) {
    String detail = "Body".equals(ex.field())
            ? ex.getMessage()
            : ex.field() + ": " + ex.getMessage();
    return problem(HttpStatus.UNPROCESSABLE_ENTITY, "Template not saved", detail, "TEMPLATE_MALFORMED");
}

@ExceptionHandler(RenderBoundExceededException.class)
public ProblemDetail handleRenderBoundExceeded(RenderBoundExceededException ex) {
    return problem(HttpStatus.UNPROCESSABLE_ENTITY, "Template not saved",
            "Validation took too long or produced too much content to render safely. "
                    + "Simplify the template (fewer nested sections or shorter loops) and try again.",
            "RENDER_BOUND_EXCEEDED");
}
