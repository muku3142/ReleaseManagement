The seeding mechanism already established in this codebase (`config/JiraSiteConfigSeeder.java`) —
copy this shape exactly:
```java
@Component
public class JiraSiteConfigSeeder implements ApplicationRunner {

    private final JiraSiteConfigService service;
    private final String defaultBaseUrl;

    public JiraSiteConfigSeeder(JiraSiteConfigService service,
                                 @Value("${app.jira.default-base-url}") String defaultBaseUrl) {
        this.service = service;
        this.defaultBaseUrl = defaultBaseUrl;
    }

    @Override
    public void run(ApplicationArguments args) {
        service.seedIfAbsent(defaultBaseUrl);
    }
}
```
V1, V2 and V3 seed no rows via SQL — `ApplicationRunner` plus an idempotency guard is the only
seeding path this project has, and D-04-14 must follow it rather than adding a Flyway `INSERT`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| classpath resource → template body | The starter bodies ship inside the jar and are persisted as templates on first start |
| startup seeding → database | The seeder writes rows before any user request is served |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-30 | Tampering | A shipped starter using a placeholder the catalog no longer defines, silently degrading every generated document | mitigate | The seeder saves through `TemplateService.saveContent`, which runs the full TMPL-04 validation render, and `TemplateSeederIT` re-asserts zero warnings and zero malformed constructs for all three starters and all four chrome fields |
| T-04-31 | Tampering | Seeding overwriting the release manager's own templates on every restart | mitigate | The guard is "this document type already has any template" — asserted idempotent by `TemplateSeederIT` tests 6 and 8 |
| T-04-32 | Denial of Service | A starter body that trips the render bounds and kills startup | mitigate | The starters render against `SampleReleaseView` (three items), far below `app.template.render.max-collection-size` of 500; `TemplateSeederIT` test 3 renders every starter as part of the build |
| T-04-33 | Elevation of Privilege | A starter smuggling a construct outside D-04-06's subset into the shipped product | mitigate | `grep -E "\{\{>|\{\{&|\{\{\{|\{\{=" src/main/resources/templates/*.md` is an acceptance criterion, and `TemplateScanner` would reject it at seed time regardless |
| T-04-34 | Repudiation | Seeded templates with no recorded author | mitigate | The seeder passes the same `SEED_ACTOR` constant `JiraSiteConfigService` already uses, so `created_by`/`updated_by` are populated and a seeded template is distinguishable from a hand-authored one |
</threat_model>
