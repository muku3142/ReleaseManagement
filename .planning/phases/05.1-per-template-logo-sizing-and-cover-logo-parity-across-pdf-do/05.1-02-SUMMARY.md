# Phase 05.1 Plan 02: Cover logo height control and mm-sized rendering Summary

**Added a bounded "Cover logo height (mm)" number input to the Chrome & Logo tab and replaced `RenderedDocument.tsx`'s hard-coded `max-h-20` with an inline `maxHeight: '<n>mm'` style, fixing the browser leg of the PDF/DOCX/browser sizing disagreement for both the authoring preview and the document viewer at once through the one shared component.**

## Performance

- **Duration:** ~20 min
- **Completed:** 2026-08-11T15:36:02+03:00
- **Tasks:** 2/2 completed
- **Files modified:** 10 (3 production, 7 test)

## Accomplishments

- `ChromeFields` in `frontend/src/api/templates.ts` gained a required `logoRenderHeightMm: number`, picked up by `api/documents.ts` for free through its existing import — no separate edit needed there.
- `ChromeFieldsForm.tsx` gained a `type="number"` input (`min={5} max={120} step={1}`, labelled "Cover logo height (mm)"), placed after the page-numbers checkbox and before the "All seven fields above stay editable" comment (updated from "six"). It deliberately carries no `onBlur`/`onSelect`/`trackSelection` and `ChromeFieldName` is untouched — verified by an unchanged `trackSelection` occurrence count (9) and the exact pre-existing union string still present verbatim.
- `RenderedDocument.tsx`'s cover `<img>` now carries `style={{ maxHeight: '${chrome.logoRenderHeightMm}mm' }}` in place of the `max-h-20` class, with a comment explaining the inline-style deviation from the file's className-only convention and citing D-05.1-06 (max-height, never scale-up). Because both the authoring preview (`TemplatePreview.tsx`) and the document viewer (`DocumentViewerRoute.tsx`) render through this one shared component, both are fixed by this single edit — confirmed by an empty `git diff --stat` against both files plus `TemplateDetailRoute.tsx` and `LogoUpload.tsx`.
- Seven test fixtures repaired with `logoRenderHeightMm: 30` (the plan-01 default), keeping every existing assertion's meaning unchanged.
- `ChromePreview.test.tsx`'s old `img.max-h-20` test (which asserted the exact class this plan deletes) was replaced with two tests: presence/absence of the cover logo via `img.mx-auto`, and a new test proving `img.style.maxHeight === '55mm'` when `chrome.logoRenderHeightMm` is 55, with an explicit check that no `max-h-` class is reachable by any path.
- `TemplateDetailRoute.test.tsx` gained `savingSendsTheEditedCoverLogoHeight`, which clicks into the Chrome & Logo tab, asserts the input's `min`/`max`/initial value (`5`/`120`/`30` from the loaded template), edits it to `65`, saves, and asserts `"logoRenderHeightMm":65` reaches the PUT body.
- Frontend suite: **185 tests passed, 0 failed** (183 baseline + 2 new), `tsc -b` clean on two consecutive runs. No Java file touched — `git diff --stat -- src/` (the backend tree) is empty.
