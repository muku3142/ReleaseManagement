## Decisions Made
- **Selection hands upward, not an owned dialog** (`D-05.2-07`, resolved in the plan's `<the_extraction_seam_resolved>`): `TicketBrowser` takes `actionLabel: string` and `onAction: (ticketKeys, jiraProjectKey) => void` rather than owning `AddToReleaseDialog`. This is the seam plan `05.2-03`'s release-page dialog depends on — a fixed-release destination without a mode flag on the shared browser.
- **`jiraProjectKey` rides along with the selection** because `TicketsRoute` needs `browsedProjectKey` (the `D-03-05` advisory project key) for `AddToReleaseDialog`, and that value is derived from state now internal to `TicketBrowser`. The release-page caller is free to ignore the second argument.
- **Bare fragment return**, not a wrapper `<div>`, so the rendered DOM under `TicketsRoute`'s `div.w-full` is unchanged and the characterization suite (which asserts on cell text, labels and `aria-label`s, never on structure) has nothing to trip over.
