# Phase 08 — UI Design Contract: Release Insights Dashboard

> Visual and interaction contract for AUDIT-04, INSIGHT-01, INSIGHT-02, INSIGHT-03 and the DOC-09 /
> ladder roll-up, on the home route `/` (D-08-10). Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. Extends the Phase 2-7 design language: no new component library, no chart library
> (D-08-09), no new icon library, no new colour, no new type size. The new visual elements are
> (1) a summary strip, (2) a wide release matrix whose cells compose existing pieces (ReadinessPill,
> Phase 7 stage dots, Phase 6 CodeLinks chip colours), (3) a one-segment-per-status inline bar, and
> (4) a deployment-history table with server-side filters kept in URL search params.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled Tailwind as in Phases 1-7. No `components.json`. Not reopened. |
| Preset | not applicable |
| Component library | none — native `<table>`, `<select>`, `<input type="date">`, `<button>`, `<ol>`. Reuse `ReadinessPill` (unchanged), the `PromotionSection` stage-dot markup (extract to a shared `LadderDots` component taking a `compact` option; planner's call), and `CodeLinksChip` colour map (`CHIP_COLOURS`). |
| Chart library | none (D-08-09). Inline bars are `div` elements with a Tailwind width (`style={{ width: pct }}` is the one allowed inline style). |
| Icon library | none — plain glyphs only (`▸`/`▾`, `—`, `·`, `↑`/`↓` not used). Pending state is the existing `animate-spin rounded-full border-2 border-gray-300 border-t-blue-600` spinner. |
| Font | system default (Tailwind `sans`), unchanged. |

Stack derived from the codebase: Vite, React, TypeScript, TanStack Query + Router (`validateSearch`
already used by `router.tsx`), Tailwind. Dashboard data comes from one dedicated endpoint plus the
existing `GET /api/documents/readiness` and the ladder query (`useEnvironmentLadder`).

## Spacing Scale

Reuses the Phase 2-7 scale exactly. No new tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Glyph gaps, pill padding, bar-to-label gap |
| sm | 8px | Compact stacks, filter control gaps, stage-dot gaps (`gap-2`) |
| md | 16px | Table cell padding (`px-4 py-2`), summary tile padding |
| lg | 24px | Section card padding (`p-6` where a section is a card; tables keep `px-4 py-2`) |
| xl | 32px | Gap between the three major sections (`mt-8`) |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions: inline bars are 8px high (`h-2`) and 64px wide (`w-16`) — both multiples of 4. The stage
dot stays `h-3 w-3` (12px) exactly as Phase 7 declared it.

## Typography

Reuses the four-role scale from Phase 5 verbatim. No new size, no new weight.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Label | 14px (`text-sm`) | 600 | 1.5 |
| Heading | 16px (`text-base`) | 600 | 1.2 |
| Display | 18px (`text-lg`) | 600 | 1.2 |

Usage this phase:
- Page title "Dashboard" and section headings ("Release matrix", "Deployment history"): Heading 16/600.
- Summary-strip figures: Display 18/600; their captions Body 14/400 `text-gray-600`.
- Table headers: Label 14/600 `text-gray-700`; cells Body 14/400.
- Pills, bar captions, footnotes, secondary lines inside a cell: `text-xs` (12px), matching the readiness
  pill and CodeLinks chip precedent. `text-xs` is the existing "dense grid cell" size, not a fifth role.
- Numbers in the matrix and summary use `tabular-nums` so columns align.

## Color

Reuses Phase 2-7 values; **no new colour is introduced**.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `gray-50` | Page canvas, empty-state panels |
| Secondary (30%) | `white` | Summary tiles, matrix and history table surfaces (`rounded border border-gray-200 bg-white`) |
| Accent (10%) | `blue-600` | See reserved-for list |
| Destructive | `red-600` / `red-700` | Error alerts; FAILED outcome text and the "Last promotion failed" marker |
| Warning | `amber-600` text/border, `amber-50` bg | Stale pill (existing); outlier-ticket flag; "incomplete"; ROLLED_BACK text `amber-700` (existing) |
| Success | `green-700` / `green-50` pill; `green-600` inline text | Up to date pill (existing); SUCCESS outcome text `green-700` (existing) |

Accent (`blue-600`) reserved for:
1. Release-name links in the matrix and history (rows link to the release, D-08-08).
2. Reached stage dots (`bg-blue-600`) and the current-stage ring (`ring-blue-300`), exactly as Phase 7.
3. Focus-visible rings on the filter controls and toggle.
4. "Clear filters" and "Try again" text links.
No primary filled button exists on this screen: the dashboard is read-only, so there is no `bg-blue-600` CTA.

Inline-bar segment colours (all existing semantic families, reused from the CodeLinks chip map so
"linked" looks the same here and on the release page):

| Segment | Fill | Meaning |
|---------|------|---------|
| Linked | `bg-blue-600` | Jira-backed items with ADO code links (includes `LINKED` flagged incomplete, D-06-03) |
| No link | `bg-gray-300` | Items with no ADO link |
| Enrichment failed | `bg-red-600` | ADO-03 failures |
| No data | `bg-gray-100` with `border border-gray-300` | `NOT_ATTEMPTED` — deliberately lightest so it reads as "unknown", never as "no link" (D-08-04) |
| Manual items | not drawn in the bar | Excluded from the denominator; shown as text |

Colour is never the only signal: every segment has a count in the cell text or `title`/`aria-label`.

Failed-promotion marker: the stage dot a latest FAILED promotion tried to reach renders as a hollow
dot `border-2 border-red-600 bg-white` (same 12px size) beside the filled reached dots, plus the
text pill "Last promotion failed" (`rounded border border-red-600 bg-red-50 px-2 py-0.5 text-xs
font-semibold text-red-700`). Failed never advances the stage (D-08-02).

## Screen Layout & States

### Primary visual anchor

**The release matrix** (section 2) is the one focal element, as the table is on `/releases`. The
summary strip is a quiet orientation row above it; the history panel is subordinate below it. Visual
hierarchy inside the matrix is carried by colour only where action is needed: amber Stale pills, the
red failed marker and amber outlier flags pull the eye; everything else is gray/neutral text.

### Route: `/` (replaces `DashboardRoute` in place; no router or nav change, D-08-10)

Page wrapper unchanged from the app shell. Top to bottom, `space-y-8` (32px):

**1. Summary strip** (`grid grid-cols-2 gap-4 lg:grid-cols-5`; each tile `rounded border border-gray-200 bg-white p-4`)
- Tiles: Need paperwork · Stale · Median created → frozen · Median frozen → production · Releases per stage.
- Figure in Display 18/600 `tabular-nums`; caption Body `text-gray-600`. A median with no data shows
  `—` and `title="No release has reached this point yet"`.
- **Releases per stage** tile: a compact `<ul>` of "{StageName} {count}" in ladder order, `text-xs`,
  plus **"Not promoted {n}"**. Retired stages with zero releases are omitted; with releases they appear
  with " (retired)".
- "Need paperwork" and "Stale" are plain numbers (not links); no filtering is triggered from tiles
  (assumption: keeps the screen free of a second filter model).
- All values computed over the visible set (D-08-11). Each tile has the "Over {n} visible releases"
  footnote once, as a single line under the strip rather than repeated per tile.

**2. Release matrix**
- Header row: heading "Releases", caption, and the **Show all releases** checkbox right-aligned
  (`flex items-center justify-between`).
- Table: `overflow-x-auto rounded border border-gray-200 bg-white`, `min-w-full text-sm`, same
  header/row classes as `ReleasesRoute` (`px-4 py-2`, `hover:bg-gray-50`, `border-b border-gray-100`).
  Release column is sticky-left (`sticky left-0 bg-white`) so the name stays visible while scrolling
  horizontally on narrower screens. No paging (out of scope); sorted newest-created first, stable.
- Documents: three sub-columns rendered by `ReadinessPill` exactly as on `/releases`; readiness is
  looked up through a `Map` index (CONTEXT discretion), never recomputed client-side (T-05-55).
  `NO_TEMPLATE` renders as the existing "No template" italic gray link.
- Each row has `title`-bearing cells per the Copywriting Contract; there is no row expansion
  (assumption: the release page already holds per-ticket detail, D-08-07 puts per-ticket figures on
  the release page, not here).
- Outlier tickets (D-08-07): the cell shows only the count of outliers. Naming them is on the release
  page. The matrix cell links the count to `/releases/$releaseId` (the tickets section).
  Outlier rule is backend-defined; the UI only renders the count.
- `<tfoot>` row "Median (visible)" repeats medians for the two duration columns only.
- Footnotes: churn disclaimer and denominator footnote beneath the table, `text-xs text-gray-500`.

**3. Deployment history**
- Section card `rounded border border-gray-200 bg-white p-4`.
- Filter bar: `flex flex-wrap items-end gap-4`; each control has a visible `<label>`
  (`text-xs text-gray-600`) above it; controls use `rounded border border-gray-300 px-3 py-1.5 text-sm`.
- Filters live in URL search params via `validateSearch` on the dashboard route:
  `env?: string` (stage id), `from?: string` (ISO date), `to?: string` (ISO date), `all?: boolean`
  (show-all-releases toggle). Absent params mean defaults (all environments, last 30 days, toggle off).
  Changing a filter replaces history (`navigate({ replace: true })`), so Back does not walk through
  every keystroke. Invalid values are dropped to defaults, not errors. A `from` later than `to` is
  swapped silently, not blocked.
- Filtering is server-side; the query key includes the filter values. Changing a filter keeps the
  previous table visible at `opacity-60` (`placeholderData: keepPreviousData`) rather than blanking.
- Table columns per Copywriting Contract; release name links to its release. Rows newest `deployed_at`
  first. No paging in this phase beyond a server-side cap (assumption: backend returns at most 200
  rows and the summary line reads **"Showing latest 200 of {n}. Narrow the date range to see more."**
  when capped).

### States

| Surface | Loading | Empty | Error |
|---------|---------|-------|-------|
| Summary + matrix | spinner + "Loading dashboard…" in place of both | per Copywriting Contract (two variants) | red alert + Try again |
| History | spinner + "Loading deployment history…" | per Copywriting Contract | red alert scoped to section |

### Interaction and accessibility
- Every interactive element is native: checkbox, `<select>`, date inputs, links, buttons. No drag, no
  custom gestures, no hover-only information: every `title` tooltip text is also the cell's
  `aria-label` or visible `text-xs` text, because touch and keyboard users do not see `title`.
- Stage dots keep Phase 7's `<ol aria-label="Environment ladder">` with `aria-current="step"`; in the
  matrix each ladder gets `aria-label="Environment ladder for {release name}"`.
- Inline bars: `role="img"` with `aria-label="{linked} linked, {noLink} no link, {failed} failed, {noData} no data"`.
- Table headers use `scope="col"`; the Documents group header uses `colSpan={3}` with a second header row.
- Cache: promotion, correction and enrichment mutations invalidate the dashboard query key
  (CONTEXT discretion); the UI shows no manual refresh button (assumption).

## Assumptions recorded (not settled by CONTEXT or prior UI-SPECs)

1. Summary tiles are not links and do not filter the matrix.
2. No row expansion in the matrix; per-ticket detail stays on the release page.
3. History is capped server-side (200 rows) with a notice, since paging of the matrix is out of scope and CONTEXT is silent on history paging.
4. Filter changes use `replace` navigation; the "show all" toggle is a URL param (`all`) so a shared link reproduces the view.
5. No manual refresh control; data refreshes on mount, window focus (TanStack default) and mutation invalidation.
6. Release column is sticky-left for horizontal scroll; no other responsive treatment (internal desktop tool).
7. The `LadderDots` extraction from `PromotionSection` is a refactor suggestion, not a requirement.
