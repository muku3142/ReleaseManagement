  <behavior>
    - Short text (under budget) -> exactly one passage equal to the trimmed text
    - Text with three `## ` sections each ~600 chars -> sections packed greedily: no passage crosses the budget; a heading line always starts a passage when it begins a new section in that passage
    - A single 5,000-char paragraph section with no blank lines -> split at whitespace into passages each within budget; passage N+1 starts with the last <= overlapChars of passage N, cut at a word boundary
    - For every passage p from any input: `withHeader(title, p).length() <= maxChars`
    - Heading-like lines inside a ``` fenced block do not start a new section
    - CRLF input yields the same passages as LF input
    - Blank or whitespace-only text -> empty list; no passage is ever blank
    - A word longer than the budget is hard-cut (no infinite loop)
    - Constructor rejects `overlapChars * 2 >= maxChars` with IllegalArgumentException
  </behavior>
  <action>
    Write ChunkerTest first covering every behavior bullet (run it, see it fail), then implement `Chunker`:
    1. Normalise `\r\n` and `\r` to `\n`. If `text.isBlank()` return `List.of()`.
    2. Budget = `maxChars - withHeader(title, "").length()` (title header is counted, per D-09-05). If budget <= overlapChars * 2,
       throw `InvalidContentException("title is too long to leave room for content")` (titles are capped at
       rag.limits.max-title-chars=300 upstream, so this guards misconfiguration only).
    3. Split into sections: a new section starts at a line matching `^#{1,6}\s` when not inside a ``` fence (toggle on lines
       starting with ```). The heading line stays at the top of its section.
    4. Pack sections greedily into passages: append a section (joined with "\n\n") while the passage stays <= budget; otherwise
       flush. A section larger than the budget is split into paragraphs (blank-line separated) and packed the same way; a
       paragraph larger than the budget is split at the last whitespace at or before the budget (hard cut if none).
    5. Overlap applies only when a flush happens inside one section (continuation of the same section): the next passage starts
       with the tail of the previous passage, at most overlapChars long, starting at a word boundary; the continuation's packing
       budget is reduced by that tail's length plus one separator.
    6. Trim each passage, drop blanks, return in order. No regex beyond the heading and fence matches; no recursion needed.
    Keep the class small (target < 120 lines); private helper methods named for what they do.
  </action>
