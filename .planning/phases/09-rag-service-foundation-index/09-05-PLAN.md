             count(d.id) FILTER (WHERE d.status = 'FAILED')  AS failed,
             max(d.indexed_at) AS last_indexed_at

      GROUP BY c.id, c.name, c.embedding_model ORDER BY c.name

    `DocumentRepositoryAdapter implements DocumentStore` (`@Component`; `@Transactional` on upsert, delete, requeueAll).
    - upsert (single statement; D-09-11 last write wins, D-09-12 FAILED re-push retries):
      ```sql
      INSERT INTO document (collection_id, external_id, title, url, metadata, body, content_hash, status)
      VALUES (:collectionId, :externalId, :title, :url, CAST(:metadata AS jsonb), :body, :hash, 'PENDING')
      ON CONFLICT (collection_id, external_id) DO UPDATE SET
          url = EXCLUDED.url,
          metadata = EXCLUDED.metadata,
          title = EXCLUDED.title,
          body = EXCLUDED.body,
          updated_at = now(),
          status = CASE WHEN document.content_hash = EXCLUDED.content_hash AND document.status <> 'FAILED'
                        THEN document.status ELSE 'PENDING' END,
          status_reason = CASE WHEN document.content_hash = EXCLUDED.content_hash AND document.status <> 'FAILED'
                               THEN document.status_reason ELSE NULL END,
          lease_until = CASE WHEN document.content_hash = EXCLUDED.content_hash AND document.status <> 'FAILED'
                             THEN document.lease_until ELSE NULL END,
          content_hash = EXCLUDED.content_hash
      RETURNING status
      ```
      (`content_hash` is assigned last for readability only; in Postgres all CASE expressions see the pre-update row.) Null
      metadata is stored as `{}`. Return `DocumentStatus.valueOf(status)`.
      Clearing the lease on a content change lets the new text be claimed; the in-flight stale embed then fails the
      `content_hash` guard in `IndexQueue.complete` (plan 06), so it is discarded (D-09-11). Old chunks stay searchable until the
      new embedding lands (RESEARCH A6 adopted: serve-old-until-new-ready, so a document does not vanish during an Ollama outage).
    - delete: `DELETE FROM document WHERE collection_id = :collectionId AND external_id = :externalId` -> rows == 1 (chunks cascade).
    - find: select all DocumentView columns (never `body`).
    - requeueAll: `UPDATE document SET status = 'PENDING', status_reason = NULL, lease_until = NULL, updated_at = now() WHERE collection_id = :collectionId`
      -> row count. Chunks are kept (RESEARCH Open Question 4 adopted: search keeps working during a re-index).
    - queueDepth: `SELECT count(*) FILTER (WHERE d.status='PENDING'), count(*) FILTER (WHERE d.status='FAILED') FROM document d JOIN collection c ON c.id = d.collection_id WHERE c.client_id = :clientId`.
    `CollectionDocumentPersistenceIT` (same setup as ClientPersistenceIT; create client + collection via the stores; chunks
    inserted with SQL using a 768-dim literal). Tests:
    1. first push -> PENDING; row has body, content_hash, metadata jsonb equal to the input map (string and number preserved)
    2. same hash on an INDEXED doc (status set via SQL) with new url and metadata -> stays INDEXED, url/metadata updated, indexed_at unchanged
    3. new text on an INDEXED doc with a lease -> PENDING, lease_until NULL, status_reason NULL, existing chunk rows still present
    4. same hash on a FAILED doc -> PENDING with status_reason NULL (D-09-12)
    5. delete returns true and the document's chunk rows are gone; delete of an unknown id returns false
    6. find never returns another collection's document with the same external id
    7. requeueAll on 3 docs (INDEXED, FAILED, PENDING) returns 3, all PENDING, chunk rows still present
    8. queueDepth counts only the given client's documents (second client with its own pending doc is excluded)
