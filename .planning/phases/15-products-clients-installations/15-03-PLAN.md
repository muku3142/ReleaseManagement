<interfaces>
API CONTRACT (JSON; all ids are UUID strings; all instants ISO strings). Backend plans 08, 11, 12 implement exactly this.

Products
- `GET /api/products` -> `{ products: Product[] }`, `Product = { id, name, archived: boolean, clientCount: number, releaseCount: number }`, ordered by name case-insensitively, archived last.
- `POST /api/products {name}` (201), `PUT /api/products/{id} {name}`, `POST /api/products/{id}/archive`, `POST /api/products/{id}/unarchive` -> each returns `{ products: Product[] }`.

Clients
- `GET /api/clients` -> `{ clients: Client[] }`, `Client = { id, name, archived: boolean, productIds: string[] }`, same ordering.
- `POST /api/clients {name}` (201), `PUT /api/clients/{id} {name}`, `POST /api/clients/{id}/archive`, `POST /api/clients/{id}/unarchive` -> `{ clients: Client[] }`.
- `GET /api/clients/{id}` -> `ClientDetail = { id, name, archived, runs: ClientRun[], history: ClientInstallEntry[] }`
  - `ClientRun = { productId, productName, productArchived: boolean, hasInstalls: boolean, current: { releaseId, releaseName, releaseVersion, installedAt, inProduction: boolean } | null }` ordered by productName.
  - `ClientInstallEntry = { id, productId, productName, releaseId, releaseName, releaseVersion, inProduction: boolean, outcome: InstallOutcome, installedAt, recordedAt, recordedBy, note: string | null, supersedesId: string | null, supersededById: string | null, correctionReason: string | null, effective: boolean }`, newest installedAt first, ties newest recordedAt first.
- `PUT /api/clients/{id}/products/{productId}` (link) and `DELETE /api/clients/{id}/products/{productId}` (unlink) -> `ClientDetail`.

Releases
- `ReleaseProduct = { id, name, archived: boolean, hasInstalls: boolean }`; `ReleaseSummary` and `Release` gain `products: ReleaseProduct[]` (ordered by name; never empty after V14's backfill and D-15-18, `[]` is rendered defensively as "Unassigned").
- `POST /api/releases` body gains REQUIRED `productIds: string[]` with at least one active product (D-15-18); missing or empty -> 422 `RELEASE_PRODUCT_REQUIRED`, checked before any Jira call. (The `CreateReleaseInput` type change and the request body change are made by plan 06, which owns the only call site, `AddToReleaseDialog.tsx`, and builds the picker in the same task; this plan does not touch `CreateReleaseInput`.)
- `PUT /api/releases/{id}/products {productIds: string[]}` -> `Release`; an empty list -> 409 `RELEASE_LAST_PRODUCT` (D-15-18).

Installs
- `InstallOutcome = 'SUCCESS' | 'FAILED' | 'ROLLED_BACK' | 'VOIDED'` (same values as `PromotionOutcome`).
- `GET /api/releases/{id}/installs` -> `InstallHistory = { releaseId, frozen: boolean, inProduction: boolean, products: { id, name, archived }[], entries: InstallEntry[] }`
  - `InstallEntry = { id, productId, productName, clientId, clientName, outcome, installedAt, recordedAt, recordedBy, note, supersedesId, supersededById, correctionReason, effective }`, newest installedAt first.
- `POST /api/releases/{id}/installs {productId, clientIds: string[], outcome, installedAt: string | null, note: string | null}` (201) -> `InstallHistory`.
- `POST /api/releases/{id}/installs/{installId}/corrections {outcome, installedAt, note, reason}` (201; outcome may be VOIDED) -> `InstallHistory`.

Errors: ProblemDetail with `reason`. `INSTALL_CLIENTS_REJECTED` adds `clients: { clientId, name: string | null, reason: 'NOT_LINKED' | 'ARCHIVED' }[]`.
Reason codes: PRODUCT_NAME_DUPLICATE, CLIENT_NAME_DUPLICATE, PRODUCT_ARCHIVED, CLIENT_ARCHIVED, CLIENT_LINK_HAS_INSTALLS,
PRODUCT_HAS_INSTALLS_ON_RELEASE, PRODUCT_NOT_FOUND, CLIENT_NOT_FOUND, INSTALL_NOT_FOUND, INSTALL_RELEASE_NOT_FROZEN,
INSTALL_PRODUCT_NOT_ON_RELEASE, INSTALL_PRODUCT_ARCHIVED, INSTALL_CLIENTS_REJECTED, INSTALL_ALREADY_SUPERSEDED,
INSTALL_INSTALLED_AT_INVALID, INSTALL_OUTCOME_NOT_RECORDABLE, RELEASE_PRODUCT_REQUIRED, RELEASE_LAST_PRODUCT.

Existing analogs: `frontend/src/api/promotions.ts` (types, `OUTCOME_LABELS`, `OUTCOME_COLOURS`, query key helper, setQueryData mutations),
`frontend/src/api/ladder.ts` (list mutation helper returning the whole list), `frontend/src/api/client.ts` (`apiFetch`, `ProblemDetail`, `ApiError`),
`frontend/src/api/auth.ts:63` (`REASON_MESSAGES`), `frontend/src/api/documents.ts:47` (`readinessQueryKey = ['documents','readiness']`).
</interfaces>
