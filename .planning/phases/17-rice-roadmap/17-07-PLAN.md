<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> API | user-supplied URL stored and later rendered as a link to every user |
| app -> rag-service / LLM | the stored URL enters tool results and indexed text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-24 | Spoofing | phishing / open redirect via packages link | mitigate | `PackagesUrl.normalize`: https only, parsed host allow-list (*.sharepoint.com, onedrive.live.com, 1drv.ms), no userinfo, default port, length cap; 400 otherwise |
| T-17-25 | Tampering | `javascript:` / data URL stored XSS | mitigate | scheme must be https; frontend also renders only via href after its own check with rel="noopener noreferrer" (17-11) |
| T-17-26 | Tampering | prompt injection through the URL text | accept | URL is host-restricted and capped; the assistant only reports it; tools are read-only |
| T-17-27 | Repudiation | no audit of link changes | accept | D-17-24: no audit table exists; same as product edits (D-15) |
| T-17-28 | Denial of service | tool result size | mitigate | URL capped at 2048 chars, well under the 8000-char tool result limit |
</threat_model>
