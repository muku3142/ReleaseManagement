  <behavior>
    SprintCheckRules:
    - Scope: when `nextSprint` is non-empty, use the items of the future sprint with the earliest startDate (null start: lowest sprint id) taken from each issue's `sprints` with state "future"; else the first `settings.thresholds().backlogItems()` of `backlog` (already ranked)
    - Essential checks: acceptance criteria present (`acceptanceCriteriaPresent`), estimate (storyPoints != null; "not checked" when `fields.storyPoints() == null`), parent epic (parentKey != null)
    - Advisory checks: sub-tasks exist (subtaskCount > 0); no open-question marker in description (a line ending with "?", or the words TBD, TBC or "open question", case-insensitive); story statement ("as a" and ("i want" or "so that"), case-insensitive); a negative case (description contains one of: invalid, error, fail, reject, "should not", "must not", negative)
    - Payment checks (advisory, listed as "not mentioned", never change the rating): idempotency, audit, maker-checker, return path ("return" or "reversal"), "ISO 20022"; only for items whose summary or description mentions payment, transfer or ISO
    - rate: YES = all essential pass and at most one advisory missing; NO = two or more essential missing; otherwise PARTLY. A "not checked" essential counts as neither pass nor missing
    - One section "Sprint or backlog items checked": first item (no key) "Checked: next sprint {name}" or "Checked: top {n} backlog items (no future sprint)"; then per issue `{summary}: {Yes|Partly|No}. Missing: {comma list}` (or "Missing: nothing"), appending "; not checked: estimate" when applicable and "; not mentioned: …" for payment checks; items sorted No, Partly, Yes, then input order
    - attention = count of Partly + No; status ATTENTION when > 0, QUIET when no items were checked, else OK
    - headline "{k} of {n} items not ready for {sprint name|the backlog} in {product}" or "All {n} items ready for … in {product}" or "No sprint or backlog items to check in {product}"; summary line 1 counts per rating, line 2 "Fix first: KEY, KEY, KEY" (top 3 No then Partly) or omitted
    WeeklyStatusRules (now = Thu 2026-10-29 13:41 Cairo, weekStart = Sun 2026-10-25 00:00 Cairo):
    - Completed = `completed` with resolved >= weekStart and statusCategory DONE; In progress = `inProgress` with statusCategory IN_PROGRESS; Blocked = isBlocker over inProgress ∪ (activeSprintAll not DONE), de-duplicated; Newly added = `added` with created >= weekStart; Overdue = dueCandidates not DONE with dueDate < today
    - Sprint committed vs done: if activeSprintAll is empty, one item "TBC: no active sprint found"; else "Current sprint scope: {n} issues ({p} points); done {d} ({dp} points)" with points "TBC" when any storyPoints are null for all issues
    - Overall: TBC when activeSprintAll is empty and blocked+overdue == 0; OFF_TRACK when blocked+overdue >= 3, or done-ratio (by issue count) < 0.5 and the sprint's endDate is within 2 working days of now; AT_RISK when blocked+overdue >= 1; else ON_TRACK
    - risks = |blocked| + |overdue|; decisions needed = blocked issues with null assignee; attention = risks + decisions; status ATTENTION when attention > 0 or overall in {AT_RISK, OFF_TRACK}; QUIET when every bucket is empty; else OK
    - Sections in order: "Completed", "In progress", "Blocked" (items "{summary} ({blockerReason})"), "Newly added", "Sprint committed vs done", "Overdue", "Executive draft", "Engineering draft"
    - Executive draft items (no keys, 5-8 lines): "Overall status: {label} — {reason}"; "Outcomes delivered: {n} issues completed"; "Top risks: {k} blocked, {o} overdue" (or "Top risks: none known"); "Decisions needed: {KEY …} (owner TBC, date TBC)" or "Decisions needed: none"; "Next milestone: {active sprint name} ends {yyyy-MM-dd}" or "Next milestone: TBC"
    - Engineering draft items: "Completed: KEY, KEY" (or "Completed: none"), "In progress: …", "Blocked: KEY ({reason}), …", "Next week's focus: TBC", "Dependencies: TBC"
    - headline starts with the overall label: "{label}: {c} completed, {b} blocked, {o} overdue in {product}" (<= 140)
  </behavior>
