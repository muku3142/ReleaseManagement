# Phase 17.1 Plan 12: App fallback runs in GET /api/briefings Summary

GET /api/briefings now returns, per task, `appFallback`, `appLatest` (one app run per active product, shown only when Claude's latest row is absent, failed or older) and `appRuns` (all app runs, newest first), using the field names that 17.1-09's `AppBriefingRun` type expects.

## What was built

- `BriefingService.overview()` makes one `ProductRepository.findAll()` call, then for each of the five tasks in enum order calls `readPort.feed(task)`. Only for `appFallback` tasks does it also call `runs.findByTask(task)`. For each product it takes the newest run that is not a `CLAUDE_COVERED` marker. `NO_JIRA_PROJECT` skipped runs still count. That run goes into `appLatest` if the product is not archived and Claude is not working, or if the run finished after Claude's latest row. Archived products' runs appear only in `appRuns`, with their product name. `feeds()` is unchanged.
- `BriefingsResponse.Task` gained `appFallback`, `appLatest` and `appRuns`, plus new records `AppRun`, `Section` and `Item`. `runAt` is set to `finishedAt`, `trigger` is sent as lowercase, and `key` comes from `issueKey`. The controller calls `overview()` and still has exactly one `@GetMapping`.
