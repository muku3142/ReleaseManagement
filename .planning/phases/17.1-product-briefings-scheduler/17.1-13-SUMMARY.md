# Phase 17.1 Plan 13: Briefing config reader and settings service Summary

**Reads Claude's project coverage and threshold defaults from briefings/config.json, using the same rules as the other briefing file reads: bounded size, no symlinks, keys filtered. Adds a settings service that resolves database override, then config.json, then the built-in default; turns days and a time into a Cairo cron; designates the scheduler user without decrypting anything; and stores the D-17.1-24 "Claude unavailable" switch, which is off by default.**

## Performance

- **Duration:** ~25 min
- **Completed:** 2026-10-26
- **Tasks:** 3/3
- **Files:** 8 created, 7 modified

## Accomplishments
- `BriefingConfigFileAdapter` takes the project list from `tasks.<id>.projects` when present, otherwise from `jira.projects`. Keys are upper-cased and anything that fails `PROJECT_KEY` is dropped. Thresholds are range-checked (stale 1-30, due 1-60, backlog 1-100, keepRuns 10-500), and an out-of-range value is read as absent. A missing, malformed, oversized, symlinked or non-object file returns `UNREADABLE`, and the log line carries only the exception class name. The adapter never reads `site` or `cloudId`.
- `BriefingSettingsService` implements the contract in the plan's `<interfaces>` section. `save` rejects everything in the validation table with `BRIEFING_SETTINGS_INVALID` before anything is written. A disabled task with no days keeps the days from its previous cron, or SUN if there are none. `designateMe` takes no account id, checks the caller through `ActorDirectory.findEmailsByAccountId`, and stores only the id.
- `fallback_enabled BOOLEAN NOT NULL DEFAULT FALSE` is added to V19 in place. It is mapped through the record, the entity and the adapter, and exposed through `setFallbackEnabled(boolean, String)` and `View.fallbackEnabled`.
