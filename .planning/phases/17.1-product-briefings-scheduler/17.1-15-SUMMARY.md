# Phase 17.1 Plan 15: Briefing settings API, run now and the fallback switch

**/api/settings/briefings endpoints for view, save, self-designation, run now and the D-17.1-24 fallback switch. Run now reports a rejected scheduler credential as a `needsCredential` count with HTTP 200, never as a 401.**

## Performance

- **Duration:** about 25 min
- **Completed:** 2026-10-26
- **Tasks:** 3 of 3
- **Files:** 6 created, 4 modified

## Accomplishments
- `BriefingRunNowService.runNow(taskId)` resolves the task. Unknown and display-only ids give `BRIEFING_TASK_NOT_RUNNABLE`. A disabled saved task gives `BRIEFING_TASK_DISABLED`. Otherwise it calls `BriefingRunner.runNow(task, settings.effective(task))` and counts the recorded runs by status (`products` = runs that are not SKIPPED).
- `BriefingSettingsController` covers GET, PUT (Bean-validated `BriefingSettingsRequest` mapped to `Update`), PUT `/scheduler-user` (no body), PUT `/fallback` (`{"enabled": boolean}`, `@NotNull Boolean`) and POST `/tasks/{taskId}/run`.
- GlobalExceptionHandler has one new `@ExceptionHandler(BriefingRejectedException.class)` with an exhaustive switch: 422, 400, 400 and 409, where reason = the enum name. No existing handler was changed.
- The settings JSON now carries `fallbackEnabled` (from 17.1-13's View), and the frontend type includes it. `useSetBriefingFallback()` writes the response into `['briefing-settings']` and invalidates `['briefings']`.
- The first row of Settings > Briefings is a `<button role="switch" aria-checked>` labelled "Claude unavailable: run briefings in the app". It has the specified helper text and an "On"/"Off" text label next to it. It saves on click, separately from "Save settings". While the save is pending it is disabled and shows a spinner. On error it shows `messageForReason`.
