# Phase 17.1 — UI Design Contract: Product Briefings Scheduler

> Visual and interaction contract for BRIEF-06, BRIEF-07 and BRIEF-08. Three surfaces: (1) the read-only `/briefings` page, (2) a "Briefings" section on the Settings page, (3) per-product Jira project keys on the Portfolio Products tab. Extends `17-UI-SPEC.md` (tokens, buttons, dialog and state patterns, `ProductFilter`) and `16-UI-SPEC.md`. No new dependency, component library, chart library, icon library, type size or font weight.

Locked inputs, not reopened: decisions D-17.1-01..21 in `17.1-CONTEXT.md` and the page contract in `scheduledTasks/briefings-build-prompt.md` (header and summary line, per-task cards, the five status pills, h1-h3 bullets, Africa/Cairo times, cross-task history table, loading / error-with-retry / empty states in the style of `PortfolioRoute`, per-card "Couldn't read this briefing's file", nav link, tests F1-F5). This spec adds what D-17.1-14 and BRIEF-06/07 need on top: app-fallback results, two extra statuses, a Source column, briefing settings and product keys. Items marked **(discretion)** are choices made here so the planner does not have to.

All briefing text, from Claude or from the app, is plain text only (D-17.1-17): React text children, no `dangerouslySetInnerHTML`, no markdown, no templating. Status is never conveyed by colour alone: every status is a word in a pill.

## Screen: Briefings (`/briefings`)

Route: `/briefings` under `authenticatedRoute`; readable by every signed-in user. Nav: link **"Briefings"** in `AppShell` after the last of Portfolio and Roadmap (Phase 17 adds "Roadmap" after Portfolio), so the order is Portfolio, Roadmap, Briefings, Assistant, Templates, Settings; same classes as the other nav links (`text-gray-600 hover:text-gray-900`, active `font-semibold text-gray-900`). The page is read-only: no write control on it.

Search params (optional, ids only, malformed dropped to default, `navigate({ replace: true })`, nothing in `localStorage`): `products` (array of product ids; empty = all). **(discretion)** The Phase 16 `ProductFilter` is reused. It filters only the app's per-product results (card rows and history rows). Claude results are not split by product, so they always stay visible; a helper line says so.

Data: `useBriefings()` on `['briefings']`, `refetchInterval` 5 minutes. Background refetches never replace the page with the loading state (keep previous data). Run times and the summary recompute on render.

Layout, top to bottom, inside `space-y-8`:

```
<h2> Briefings
Summary line
[Products: All products v]   "Claude results are not split by product and always show."
Credential notice (only when an app run needs a credential)
Cards (grid, one per task, fixed order: Daily Jira digest, Sprint backlog check, Weekly status update, Payments regulation watch, Saudi & Gulf investment brief)
Run history (heading, table, "Show more")
```

### Focal point

The visual anchor is the summary line, then the first card (in task order) whose pill is Needs attention or Run failed. Those cards are not recoloured; they are found by the pill's word and by order, and the summary line names their count above them. No card is larger than another.

### Summary line

Body `text-gray-600`, under the heading: **"{N} of 5 briefings need attention · latest run {time}"**. N counts tasks whose card pill is "Needs attention". Singular: **"1 of 5 briefings needs attention · latest run {time}"**. Zero: **"No briefing needs attention · latest run {time}"**. When some cards are "Run failed" or "Needs credential" the line adds **" · {k} failed"** and/or **" · {k} need a credential"** (words, not colour). No run anywhere: **"No briefings have run yet"**. `{time}` is the newest run time across all sources and products (see Time format).

### Credential notice

Shown when any app result in the feed has status `needs_credential` as its latest for a task and product (D-17.1-10: the user is told in the UI). `rounded border border-amber-600 bg-amber-50 p-3 text-sm text-amber-700`, `role="status"`, text exactly as D-17.1 specifics: **"The scheduler's Jira credential is missing or expired. Choose 'Use my Jira credential' in Settings > Briefings."** with "Settings > Briefings" as a blue `Link` to `/settings#briefings`. Not dismissible (it clears when the condition does).

### Card (one per task)

`<section aria-labelledby="briefing-{id}-name" className="rounded border border-gray-200 bg-white p-4">`, `space-y-4` inside, grid cell `lg:grid-cols-2 gap-4` on the page.

Header row (`flex flex-wrap items-start justify-between gap-2`):
- Left: `<h3 id=...>` task name (Heading); Small `text-gray-600` schedule text under it (from the API, e.g. **"Sun-Thu 08:44 · Africa/Cairo"**).
- Right: the status pill, then the attention count when known and greater than 0: Small **"{n} items need attention"** / **"1 item needs attention"** (`tabular-nums`, `text-gray-600`). The count is the sum over the results shown.

Card pill (and count) rules: the pill is the worst status among the results shown on the card, in this order, worst first: Run failed, Needs credential, Needs attention, All clear, Quiet, Skipped. No results and no read error: **Not run yet**. For the two display-only tasks the pill is simply their latest Claude status.

Body, in this order, each part present only when it has data:

**1. Claude result** (all five tasks). Section label: Small chip **"Claude"** (`PRODUCT_CHIP` classes) followed by Small `text-gray-600` **"Last run {time}"**.
- Headline: Label.
- Bullets: `<ul className="list-disc space-y-1 pl-5 text-sm text-gray-700">` for the non-null of `h1`, `h2`, `h3`. Each bullet is one plain text line (max 120 characters, truncated by the adapter, never ellipsised client-side).
- A Claude row with status `failed`: pill "Run failed" and Body **"Claude's last run for this briefing failed."** (the headline from the file still shows if present).
- Issue keys: see "Issue key links" below (the three Jira tasks only).

**2. App fallback results** (the three Jira tasks only; D-17.1-14). Rendered when the server returns app results for the latest slot, that is, when Claude is not working for at least one product. Section label: Small chip **"App fallback"** (`PRODUCT_CHIP` classes) and Small `text-gray-600` **"Claude's result for this slot is missing or failed, so the app ran it."** Then one row per active (non-archived) product, ordered by name (a product that Claude covers is not listed). Each product row is a `<details>` (`rounded border border-gray-200`, `px-3 py-2`):
- `<summary>` (focus ring, one wrapping line): product name (Label), status pill, **"{n} items need attention"** Small when greater than 0, Small `text-gray-600` run time, then the headline on its own line (Body). Native disclosure marker kept. `aria-label` is not needed: the summary text names the product.
- Body, `bg-gray-100 p-3` ("Full briefing", D-17.1-12), by status:

| Status | Body |
|---|---|
| `ok`, `attention`, `quiet` | A Label **"Full briefing"** title is not repeated; the body is the sections the app computed. Each section: Label title, then `<ul className="list-disc space-y-1 pl-5 text-sm">` of plain text items (issue keys linked). Section titles per task: digest **Blockers · Stale in progress · Not ready · Changes since the last run · Due soon or overdue**; sprint check **Sprint or backlog items checked** with each item as `{KEY} {title}: Yes / Partly / No. Missing: {list}`; weekly status **Completed · In progress · Blocked · Newly added · Sprint committed vs done · Overdue · Executive draft · Engineering draft**. Empty section: Small `text-gray-600` **"Nothing to report."** Unknown values read **"TBC"**. When the self-hosted model wrote the headline, nothing marks it; the facts below are the source of truth. |
| `needs_credential` | **"The scheduler's Jira credential is missing or expired. Choose 'Use my Jira credential' in Settings > Briefings."** with the blue Settings link. Pill **Needs credential**. |
| `skipped` | **"No Jira project is set for this product, so the app skipped it."** with a blue link **"Set a Jira project"** to `/portfolio?tab=products`. Pill **Skipped**. Headline line reads **"Skipped: no Jira project"**. |
| `failed` | **"This run failed. The next scheduled run will try again."** Pill **Run failed**. No technical detail is shown (nothing server-side leaks into the page). |

The first row of a card is open by default only when the card has exactly one app row; otherwise all rows start closed. Open state is not remembered.

**3. Empty and error states inside a card:**

| Condition | Body |
|---|---|
| `latest: null`, no read error, no app results | Pill **Not run yet**; Body `text-gray-600` **"No result yet. This briefing runs {schedule text}."** |
| `readError` | Pill **Unreadable** replaces Not run yet; Small `text-amber-700` **"Couldn't read this briefing's file"** (locked copy). For the three Jira tasks the app results, if any, still show below it (an unreadable folder counts as Claude unavailable, D-17.1-03). |
| Display-only task (`reg_watch`, `gulf_invest`) | Never shows an App fallback section. Not-run copy as above. |

### Issue key links

Applies to the three Jira tasks, to Claude bullets and headline and to app results. Plain text is split on the pattern `[A-Z][A-Z0-9]+-\d+`. A match becomes a link only when its project prefix is one of the Jira project keys of the products the page already knows (from `useProducts`) **and** `useJiraSite` has returned a `baseUrl`; otherwise it stays text (so "ISO-20022" or "UTF-8" are never linked). Link: `<a href="{baseUrl}/browse/{KEY}" target="_blank" rel="noopener noreferrer" className="text-blue-600 hover:underline">{KEY}</a>` followed by visually hidden **" (opens in a new tab)"**. The key text is a React text child; the surrounding text is rendered as text children. The `href` is built only from the configured Jira site and a regex-matched key, never from the briefing text beyond that key. `reg_watch` and `gulf_invest` text is never linked.

### Run history table (BRIEF-06, D-17.1-12)

Heading **"Run history"** (Heading) above a bordered table: `min-w-full text-sm` in `overflow-x-auto rounded border border-gray-200 bg-white`, header `px-4 py-2 text-left font-semibold text-gray-700`, rows `border-b border-gray-100 hover:bg-gray-50`, cells `px-4 py-2`, headings `scope="col"`, `<caption className="sr-only">Run history, newest first</caption>`.

Rows: every Claude run and every app run of all five tasks, merged, newest first by run time (the product filter removes app rows of unselected products only). Columns, in this order:

| Column | Cell |
|---|---|
| **Task** | Task name (Label) |
| **Product** | Product name for app runs; `—` (`text-gray-400`, `title="Claude results are not split by product"`) for Claude runs |
| **Source** | Small chip **"Claude"** or **"App fallback"** (`PRODUCT_CHIP`) |
| **Run** (heading "Run (Cairo)") | `<time dateTime={run_at}>` in the Time format, `tabular-nums` |
| **Status** | The status pill (same labels and classes as cards) |
| **Headline** | Plain text, `min-w-[16rem]`, wraps |
| **Needs attention** | Integer, `tabular-nums`; `—` when null or the run is `skipped` or `needs_credential` |

Initial page: the newest 50 rows. A bordered button **"Show more"** after the table adds 50 more, hidden when none remain; the Small `text-gray-600` line **"Showing {shown} of {total} runs."** sits beside it. (Runs are already capped per task by the adapter at 60 and per task and product by `keepRuns`, so the table is bounded.) Rows are not expandable; the card holds the full briefing.

### Time format

All times are rendered in Africa/Cairo regardless of the browser zone: `Intl.DateTimeFormat('en-GB', { timeZone: 'Africa/Cairo', weekday: 'short', day: 'numeric', month: 'short', hour: '2-digit', minute: '2-digit', hourCycle: 'h23' })`, e.g. **"Sun 25 Oct, 08:44"**, with the full ISO string in `title`. The card and summary add the suffix **"Cairo"** the first time a time appears in them (**"Last run Sun 25 Oct, 08:44 Cairo"**); the table says it once in the column heading. An unparseable `run_at` renders **"Unknown time"** and sorts last.

### Page states

| Surface | Loading | Empty | Error |
|---|---|---|---|
| Whole page (first load) | `SectionLoading` **"Loading briefings…"** under the heading | Not applicable: the five cards always render. | `SectionError`: `role="alert"` **"Couldn't load the briefings — {message}. Try again."** + **Try again** button |
| Product filter (products fetch) | Control hidden until loaded | Hidden when no products exist | Control hidden; the page still renders; app rows show the product name from the briefings payload |
| Cards | none (page-level) | Per-card "Not run yet" as above | Per-card "Couldn't read this briefing's file" as above |
| Run history | none (page-level) | Panel `rounded bg-gray-50 p-6 text-center`, heading **"No runs yet"**, body **"Runs appear here after a briefing's first scheduled run."** | Part of the page-level error |
| Product filter hides everything in the table | none | Heading **"No runs match this filter"**, body **"Choose different products. Claude's runs are always shown."** with **"Clear filter"** blue text link | none |

## Screen: Settings, Briefings section (BRIEF-07, D-17.1-10, D-17.1-11)

### Placement and gating

The Briefings section lives on the existing Settings page (`SettingsRoute`), after the Azure DevOps section, as `<section id="briefings">` in a new sibling container `mt-8 max-w-3xl` below the existing `max-w-xl` container (the existing sections keep their width). The needs-credential copy links to `/settings#briefings`; the section heading has `tabIndex={-1}` and receives focus when the hash is `#briefings`.

Gating (D-17.1-18): there is no admin role. Any signed-in user may change Briefings settings and use "Run briefing now", the same as the rest of Settings. The section renders for every signed-in user; the server rejects only unauthenticated requests. Failures render in the section's `role="alert"` via `messageForReason`.

### Layout

Heading **"Briefings"** (Heading, mt-8 like the other Settings headings). Intro Small `text-gray-600`: **"Claude runs these briefings first. The app runs one itself only when Claude's result for a slot is missing or failed."** Then, inside one `<form>` with `space-y-8`:

**1. Claude feed (read-only)**: Label **"Claude feed"**, `<dl className="mt-2 space-y-2 text-sm">`:

| Term | Description |
|---|---|
| Claude data folder | The path from `app.briefings.dir` (Body, `break-all`) |
| Claude config file | The path of `briefings/config.json` (Body, `break-all`) |
| Status | **"Readable"** or **"Not readable. The app treats Claude as unavailable and runs every briefing itself."** (words only, no colour needed; the second in `text-amber-700`) |

Helper Small `text-gray-600`: **"Set by RM_BRIEFINGS_DIR on the server. Change it there and restart the app."** Both the data folder and the config file are read-only text, never editable in the UI (D-17.1-21): they are fixed by the container's read-only `./briefings` mount (which exposes `config.json` and `data/`), and a database-editable path would be a file-read risk. They are never shown on `/briefings`.

**2. Scheduler**: Label **"Scheduler"**, fields stacked `space-y-4`:

| Field | Control |
|---|---|
| Scheduler user | Read-only line: Label **"Scheduler user"**, value the designated user's {email} (Body), or **"Not set"** (`text-gray-500`). Beside it, when the signed-in user is not the scheduler user, a bordered button **"Use my Jira credential"** (pending: `disabled`, Spinner **"Saving…"**); when the signed-in user already is, the button is replaced by Small **"You are the scheduler user."** Helper Small `text-gray-600`: **"Scheduled briefings read Jira with the stored credential of the person who clicks this. Anyone can take over by clicking it."** The scheduler only reads Jira; it never writes. A user can only designate themselves, never another person (each user's own Jira credentials, PROJECT.md). Success: polite announcement **"You are now the scheduler user."** Server rejection: `role="alert"` `data-reason` via `messageForReason`; reason `BRIEFING_NO_JIRA_CREDENTIAL` -> **"You have no stored Jira credential. Sign in with a Jira API token first."** When unset or the credential is rejected: amber notice `role="status"` (`rounded border border-amber-600 bg-amber-50 p-3 text-sm text-amber-700`) **"The scheduler's Jira credential is missing or expired. Choose 'Use my Jira credential' in Settings > Briefings."** (here without a link, the user is already on the page). The designation saves on click, not with "Save settings". |
| Grace period | number input `w-24`, unit Small **"minutes"**; helper **"How long after a slot the app waits for Claude's result before it runs the briefing itself. Default 30."** |
| Work week | Seven checkboxes in a `<fieldset>` (legend Label **"Work week"**), labels **Sun Mon Tue Wed Thu Fri Sat** (`aria-label` with the full day name), default Sun-Thu ticked. Helper Small: **"Used to count working days for stale issues."** |
| Runs kept | number input `w-24`, unit Small **"runs per briefing and product"**; helper **"Older app runs are removed. Default 60."** |

**3. Briefings**: Label **"Briefings"**; three `<fieldset>` cards (`rounded border border-gray-200 bg-white p-4`, `space-y-4`, legend = task name, Label), in the order digest, sprint check, weekly status. Each contains:

- **Enabled** checkbox with Body label **"Enabled"**.
- **Slot**: legend Label **"Days"** over seven day checkboxes (same labels as Work week) and a `<input type="time">` (`w-28`, label Label **"Time"**) with Small **"Africa/Cairo"** beside it. Day pickers and a time input are used instead of a raw cron field **(discretion)**: they cover every slot the three exported tasks use and cannot be mistyped; the server stores the equivalent cron. Slot summary Small `text-gray-600` updates live: **"Runs Sun, Mon, Tue, Wed, Thu at 08:44 Africa/Cairo."**
- **Thresholds** (units in Small after the input, defaults in the helper):

| Task | Field (label) | Range | Helper |
|---|---|---|---|
| Daily Jira digest | **"Stale after"** `w-24` + Small "working days" | 1-30 | "An in-progress issue with no update for this long is stale. Default 3." |
| Daily Jira digest | **"Due soon within"** `w-24` + Small "days" | 1-60 | "Issues due within this many days are listed. Default 5." |

It ignores Claude's result."** (**discretion**: run briefing now covers all products, not one.) Pending: button `disabled` plus Spinner and label **"Running…"**. Run briefing now uses the saved settings."**; when the task is not enabled (saved) **"Enable this briefing to run it."**. Result region per card, `role="status" aria-live="polite"`, `text-sm`: **"{name} ran for {n} products. {k} need attention."** (omit zero parts; **"1 product"** singular; add **"{k} failed."** or **"{k} need a credential. **Footer**: primary **"Save settings"** (disabled while pending or when the form is unchanged); Pending: Spinner **"Saving…"**. Success `role="status"` `text-green-700` **"Settings saved."** (cleared on the next edit). Server rejection (400): `role="alert"` `data-reason={problem.reason}` `text-red-600` via `messageForReason`, plus field-level `fieldErrors` under the matching control. ### Validation (client side, advisory; the server is the authority and returns 400 for the same rules)

### Editor

Inline panel `id="product-{id}-jira-editor"`, `mt-3 rounded border border-gray-200 bg-white p-4`:
- Label (Label) **"Jira project keys"**, `<input type="text" autoComplete="off" autoCapitalize="characters">` with `FIELD`, prefilled with the current keys joined by `, `; `aria-describedby` to the helper and the error.
- Helper Small `text-gray-600`: **"The Jira project keys this product's briefings read, for example CNV. Separate several keys with commas. Leave empty to skip this product."**
- Buttons `mt-3 flex gap-2`: primary **"Save Jira projects"** (disabled when unchanged or pending) and bordered **"Cancel"**. Pending: Spinner **"Saving…"**.
- Input handling: the value is upper-cased on blur, split on commas and spaces, trimmed, de-duplicated. Each key must match `^[A-Z][A-Z0-9_]{1,9}$` (Jira's project key shape). Invalid key: Small `text-red-600` **"“{value}” isn't a valid Jira project key. Keys are letters and digits, starting with a letter, for example CNV."**; nothing is sent. Clearing the field is allowed and removes all keys (no confirmation: it is reversible and nothing is deleted).
- Success: panel closes, focus returns to the row's Edit / Set button, polite announcement **"Jira projects saved for {product}."** (one `role="status" aria-live="polite"` region on the panel).
- Server rejection (400 or 409): the panel stays open and keeps the typed value; `role="alert"` `data-reason={problem.reason}` Small `text-red-600` shows `messageForReason(problem)`. Required `messageForReason` entries (final reason codes, D-17.1-19: a Jira project key belongs to exactly one product): `PRODUCT_JIRA_KEY_INVALID` (400, malformed key) -> **"“{value}” isn't a valid Jira project key. Keys are letters and digits, starting with a letter, for example CNV."** Other failures fall through to the generic mapping, e.g. **"Couldn't save the Jira projects — {message}. Try again."**
- Saving invalidates the products query and the briefings query.

The keys are plain text everywhere (chips are text children). V19 backfills existing products from their releases' `jira_project_key`, so a product such as "CNV" already shows `CNV` on first load.

## Interaction and Accessibility

- **Native semantics.** Real `<table>` with `scope` and `<caption>`, `<details>`/`<summary>` for per-product full briefings, `<fieldset>`/`<legend>` for day pickers and task cards, `<section aria-labelledby>` per card, real `<button>`, `<select>`, `<input>`. `<time dateTime>` for run times.
- **Status is not colour alone.** Every pill carries its word; the page summary names the failed and credential cases in words; the source is a word chip; "Skipped" and "Unreadable" are words.
- **Keyboard order (`/briefings`).** Heading, product filter, credential-notice link, then per card: summary toggles of app rows, linked issue keys; then the "Show more" button. Escape closes the filter popover (existing behaviour).
- **Keyboard order (Settings section).** "Use my Jira credential" (when shown), grace period, work-week days, runs kept, then each task in order: Enabled, Days, Time, thresholds, Run briefing now; then Save settings.
- **Live regions.** Run-now results and "Settings saved." are `role="status"` (polite); errors are `role="alert"`. The 5-minute refetch is silent (no announcement); the page does not move focus or re-expand rows when data refreshes (keep rows keyed by task, product and run time).
- **Blocked actions** ("Run briefing now" with unsaved changes or a disabled task) use `aria-disabled="true"` + `aria-describedby` to a visible helper line, not `disabled`. Pending uses `disabled` plus Spinner.
- **Focus.** After a successful Portfolio editor save focus returns to the row's button; `/settings#briefings` focuses the section heading; "Run briefing now" keeps focus on itself after finishing.
- **Contrast.** 700-on-50 pill pairs, `amber-700` on white and `red-600` on white meet 4.5:1; essential text is `gray-600` or darker; `gray-400` is used only for the dash in the Product column, with a `title`.
- **Reduced motion.** The spinner is the only animation; it carries `motion-reduce:animate-none`.
- **Plain-text safety (D-17.1-15, D-17.1-17).** Headlines, bullets, section items, product names, keys, file paths and error text render as React text children. No `dangerouslySetInnerHTML`, no markdown, no HTML, no `href` built from briefing text beyond a regex-matched, known-project issue key on the configured Jira site. The page never shows file paths or file contents from a read error.
- **Cache.** `['briefings']` refetches every 5 minutes and on window focus (default). Saving settings, running a task now, and saving product keys invalidate `['briefings']`; saving product keys also invalidates `['products']`. Nothing is stored in `localStorage`; state is the `products` search param only.
- **Responsive.** Desktop-first internal tool. Cards in two columns from `lg`, one below; the history table scrolls in `overflow-x-auto`; Settings fieldsets stack; day pickers wrap.
