# Phase 17.2 Plan 04: Single-product release editor Summary

The release-detail products editor is now a single-choice radio panel. It saves through the new `useSetReleaseProduct` hook (`PUT /api/releases/{id}/product { productId }`). Once installs are recorded, "Change product" is aria-disabled and shows the visible D-15-15 reason.

## Deviations from Plan

1. **[Rule 3 - Blocking] The hook test lives in `tests/api/portfolio.test.ts`, not `releases.test.ts`.** The plan named `releases.test.ts`, but the existing `useSetReleaseProducts` cases (the URL/body case and the dashboard-invalidation `it.each` row) were in `portfolio.test.ts`, so they were updated there. `releases.test.ts` is untouched.
2. **The staleness hint was removed.** The old panel showed "Changing products marks this release's existing documents as out of date…" on OPEN releases. UI-SPEC screen 7 does not list it, so it was dropped.
3. **ReleaseDetailRoute.test.tsx:** the only change is the copy "Products:" to "Product:". The `productId` that 17.2-03 passes to AddTicketsToReleaseDialog is kept.
