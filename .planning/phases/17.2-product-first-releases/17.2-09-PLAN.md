<objective>
Add the D-17.2-06 filter to the ticket browser. A checkbox "Hide tickets already in a release", on by default, asks the server to leave out tickets that already belong to a release.

Purpose: D-17.2-06. Tickets added to a release kept showing up on the Tickets page and were picked again. There is no REQUIREMENTS.md ID for D-17.2-06; it is filed under REL-PF-01 (the ticket browser) for traceability.

Scope:
- The checkbox appears where tickets are picked for a release: the Tickets page and AddTicketsToReleaseDialog.
- It does not appear in the roadmap's AddFromJiraDialog (`TicketBrowser` without the new prop). The roadmap plans future work and is not "picking tickets for a release". Hiding released tickets there by default would change a screen D-17.2-06 does not mention.
- The filter applies on the next "Load tickets", exactly like the status checkboxes.

Server contract (17.2-10 implements it; this plan only sends it): `POST /api/tickets/search` accepts an optional boolean `hideAlreadyInRelease`. When it is true, the server drops every result whose key is on any release, whatever the release's status. Absent or false means today's behaviour. The field is orthogonal to the mode and to `releaseId`.

Output: the client body field, the checkbox and the tests.
</objective>
