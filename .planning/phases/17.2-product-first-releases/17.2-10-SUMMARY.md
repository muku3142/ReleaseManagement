# Phase 17.2 Plan 10: hideAlreadyInRelease ticket-search flag Summary

`POST /api/tickets/search` takes an optional `hideAlreadyInRelease` flag. When it is true, the search drops every ticket whose key is on any release, OPEN or FROZEN. The check is a single `select distinct ... where ticketKey in :keys` query, bounded by the keys Jira returned.

## What was built

- **Persistence:**
  - `ReleaseTicketItemJpaRepository.findTicketKeysIn` is a JPQL query with a bound `IN :keys` and `distinct`.
  - `ReleaseRepository.ticketKeysInAnyRelease` is implemented in the adapter as `@Transactional(readOnly = true)`. An empty input returns `Set.of()` without querying.
- **Service:**
  - `search(criteria, releaseScope, hideAlreadyInRelease)`: when neither the scope nor the flag is set, Jira's list comes back unchanged. Otherwise one `hidden` set is built from `findTicketKeys(scope)` and/or `ticketKeysInAnyRelease(found keys)`, and the results are filtered by it.
  - `searchProduct` passes the flag through after the PRODUCT_NO_JIRA_PROJECT check.
  - `search(criteria)` delegates with `(null, false)`, so `findByKey` and `ReleaseService` behave as before.
  - Release membership still never reaches JQL (D-05.2-02).
- **Web:** `TicketSearchRequest` gains a trailing `Boolean hideAlreadyInRelease` plus `hidesAlreadyInRelease()`, which treats null as false. The controller passes it in both the product branch and the project/JQL branch.

## Deviations from Plan

**1. [Rule 1 - Bug] The request flag is a boxed `Boolean`, not a primitive `boolean`**
- **Found during:** Task 2 GREEN.
- **Issue:** With a primitive `boolean`, every request body that omitted the property failed with a 400 (HttpMessageNotReadableException). Spring Boot 4 uses Jackson 3, which by default fails a primitive creator property that is absent or null. The plan's premise that "a missing JSON property binds to false" does not hold, and 19 existing controller tests failed.
- **Fix:** The record component is now `Boolean hideAlreadyInRelease`, and `hidesAlreadyInRelease()` returns `Boolean.TRUE.equals(...)`. The controller uses that accessor. The wire contract is unchanged: the field is optional and absent means false.
- **Commit:** 8d41fe4d
