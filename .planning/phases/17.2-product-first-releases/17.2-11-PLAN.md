<objective>
Generated documents can group by bundle (D-17.2-07): a third grouping choice, BUNDLE, next to ISSUE_TYPE and COMPONENT. Ungrouped tickets fall into an "Other" group.

Purpose: D-17.2-07, "shown as a group" in documents. V24 (17.2-08) has already widened the `template.grouping_dimension` CHECK to accept BUNDLE. This plan adds the enum value and the grouping. Filed under REL-PF-01 for traceability, since D-17.2-07 has no REQUIREMENTS.md ID.

Design choices (smallest change):
- `ItemView`, `GroupView`, `RenderContextMapper` and the catalog's tokens stay unchanged. The template data shape is identical; only the group keys differ. `PlaceholderCatalogTest`'s drift guard (catalog tokens equal record components) keeps passing.
- No `{{bundle}}` item placeholder is added. D-17.2-07 asks for grouping, not a per-item field.
- Group order:
  - bundle groups in case-insensitive alphabetical order
  - then "Other" for ungrouped tickets, only if there are any
  - then the manual-item category groups in their existing order
- "Other" is kept separate from the bundle map, so a bundle literally named "Other" stays its own group rather than absorbing the ungrouped tickets.
- The template preview endpoint keeps previewing with ISSUE_TYPE (existing D-05-04 behaviour for COMPONENT too). Only saved-template generation uses BUNDLE.

Output: the enum value, assembler grouping, the catalog description, and tests.
</objective>
