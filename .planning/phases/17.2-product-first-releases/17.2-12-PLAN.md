<objective>
Let the user name a bundle when adding selected tickets to a release, from all three entry points named in D-17.2-07:
- New release (AddToReleaseDialog with startWithForm)
- Add to release (AddToReleaseDialog list)
- AddTicketsToReleaseDialog

Purpose: D-17.2-07. "the user can optionally name a bundle … Leaving the name empty adds them ungrouped", and "At minimum, the user can add more tickets to an existing bundle by choosing it by name". Filed under REL-PF-01/02 for traceability (D-17.2-07 has no REQUIREMENTS.md ID).

Server contract (17.2-08):
- `POST /api/releases {name, version, ticketKeys, productId, bundle?}`
- `POST /api/releases/{id}/items {ticketKeys, bundle?}`
- `DELETE /api/releases/{id}/items/{key}[?withBundle=true]`
- Items carry `bundle: string | null`.
- The server reuses an existing bundle when the name matches ignoring case and spaces.

Choosing an existing bundle:
- In AddTicketsToReleaseDialog the release is known, so its bundles are offered as `<datalist>` suggestions.
- In AddToReleaseDialog the target release is picked after the name is typed, so it is a plain text input. Typing an existing bundle's name adds to it, because the server matches case-insensitively. The helper text says so.

Output: the API wrapper changes, the two dialog inputs and tests.
</objective>
