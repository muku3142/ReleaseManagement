# Phase 17.2 Plan 13: Release view grouped by bundle Summary

The release page's ticket table now shows one header row per bundle (name and ticket count, sorted by `releaseBundles()`), followed by that bundle's tickets, with an "Ungrouped" header for the rest. Remove on a bundled ticket opens a dialog offering "Remove whole bundle" (`DELETE ...?withBundle=true`), "Remove only {key}" (plain DELETE) and Cancel. Ungrouped tickets are still removed straight away.

## What was built

- `ticketGroups` is derived once from `data.items`:
  - No bundles: a single group with no header, so the table is unchanged.
  - Otherwise: one group per bundle in `releaseBundles()` order, each keeping the items' existing order, then an "Ungrouped" group if any ungrouped items exist.
- Header rows are `<th scope="rowgroup" colSpan={isOpen ? 12 : 11}>` with the bundle name as React text (T-17.2-33).
- `bundleRemoval` state (`{ key, bundle } | null`) drives a `ConfirmDialog`. The red confirm button removes the whole bundle; a secondary child button removes only the ticket. Whole-bundle removal is reachable only through that explicit button (T-17.2-34).
- Selection, select-all, expand, code-link retry and the hash anchor still key off `item.key`.
