### Styling rule for this phase

- **Themed route (`/releases`, `staticData.themed: true`).** Use token classes and owned components only. The 23-09 grep gates forbid raw `gray-*`, `blue-*`, `red-*`, `green-*` and `amber-*` classes in `ReleasesRoute.tsx`.
- **Unmigrated surfaces** (`TicketsRoute`, `TicketBrowser`, `AddToReleaseDialog`, `AddTicketsToReleaseDialog`, `ProductsEditor`, `ReleaseDetailRoute`). These render inside the `.paper` light island.
  - **New** markup uses token classes and owned components: `text-foreground`, `text-muted-foreground`, `border-input`, `bg-card`, `text-primary`, `text-destructive`, `text-warning`, plus `Alert`/`Spinner`. Tokens resolve to their light values inside `.paper`, so this looks right today and needs no work in 23.1.
  - **Existing** markup in those files keeps its current classes. Do not restyle it (CONTEXT `<domain>`; R §Standard Stack).
- New native controls copy the token form of the existing control style:
  - select: `h-9 rounded-md border border-input bg-card px-3 text-sm text-foreground`
  - radio: `size-4 accent-primary`

## Screens and Interaction Contract

### 1. Releases page `/releases`: "New release" (D-01, REL-PF-02)

| Element | Contract |
|---|---|
| Action | `PageHeader actions`: `<Button asChild><Link to="/tickets" search={{ new: true }}><Plus aria-hidden /> New release</Link></Button>`. It is the only default-variant Button on the page. |
| Empty state (no query) | `Empty` with title **"No releases yet"** and body **"Choose New release, pick a product and select its tickets."** The old "Browse tickets" link and the "'Add to release' → 'New release…'" sentence are removed. The header button is the action, so there is no second primary. |
| Empty state (query) | Unchanged |
| Products column | Unchanged. It shows one outline Badge now. The "+{n}" overflow code may stay; it never triggers. |

Only the actions slot and the empty copy change in this file (R Pitfall 5).

### 2. Command palette (consistency)

The Actions item **"Start a release from tickets"** becomes **"New release"** (`Plus`), with keywords `['New release', 'Start a release from tickets']`. It navigates to `/tickets?new=true`. **(discretion)**: this keeps a single name for the entry point.

### 3. Tickets page `/tickets` (D-01, D-03, D-04, D-05, REL-PF-01/02/04)

URL search: `{ product?: string; new?: true }` (validated in `router.tsx`, R Pattern 4).

Layout, top to bottom:

```
<h2> "Browse tickets"   or   "New release" when new=true           (Heading 16/600)
[new=true only] <p> "Pick a product, select its tickets, then name the release."  (Body, muted, mt-1)
Product field (mt-4)
  <label for="productId"> "Product" (Body 600)
  <select id="productId" class="w-64 …"> "Select a product…" + active products, A→Z
  [chosen, has keys] <p> "Searches {KEY1}, {KEY2}" (Small, muted; keys font-mono)
Then exactly one of:
  - nothing chosen  → <p> "Choose a product to browse its tickets." (Body, muted, mt-4)
  - no Jira project → Alert warning (D-17.2-04), mt-4
  - has keys        → <TicketBrowser key={productId} productId=… />  (mt-4)
```

| Rule | Contract |
|---|---|
| Product options | Active products only (`!archived`), sorted by name, option text `{name}`. A product with no keys is still listed: picking it shows the notice, so the user learns why. |
| Selection | Choosing writes `product` to the URL with `navigate({ search, replace: true })` and keeps `new`. A deep link `/tickets?product=<id>` preselects it. An unknown or archived id is treated as nothing chosen. |
| Reset | `TicketBrowser` is keyed by `productId`, so changing the product clears the loaded tickets and the selection (R Pitfall 4). |
| Products loading | `Spinner` + **"Loading products…"** in a `role="status"` line. The select is not rendered until loaded. |
| Products error | `<p role="alert" data-reason>` with `messageForReason(problem)` + an outline **"Try again"** button that refetches |
| No active products | **"No products yet. Add one in Portfolio › Products."**, with "Portfolio › Products" linking to `/portfolio?tab=products` (Body, muted, link `text-primary`) |
| Browser action label | `new=true`: **"Create release"**. Otherwise **"Add to release"** (unchanged). |

#### D-17.2-04 notice (one small shared component, used in screens 3 and 5)

```tsx
<Alert variant="warning" role="alert" data-reason="PRODUCT_NO_JIRA_PROJECT">
  <TriangleAlert aria-hidden />
  <AlertDescription>
    {productName} has no Jira project. Add one in{' '}
    <Link to="/portfolio" search={{ tab: 'products' }} className="text-primary underline underline-offset-4">Portfolio › Products</Link>.
  </AlertDescription>
</Alert>
```

- The text is exactly: **"{Product} has no Jira project. Add one in Portfolio › Products."** The product name renders as a React text child.
- While it shows, no ticket browser, no action button and no create form is reachable. That is the block. The server 422 `PRODUCT_NO_JIRA_PROJECT` is the backstop.

### 4. TicketBrowser in product mode (D-03, D-05)

The new prop is `productId?: string`. Without it the browser behaves as today: `AddTicketsToReleaseDialog` always passes it now, and nothing else renders the unscoped project mode.

| Element | Contract |
|---|---|
| Project select | Label **"Project"**. The first option is **"All {Product} projects"** (default, value `""`). Then one option per mapped key that is found in `useJiraProjects()`, with today's option text. **"All…"** searches in `{ mode: 'product', productId }`. Picking one project switches to today's `projectId` mode. The option "Select a project…" is gone. |
| Sprint select | Enabled only when a single project is picked. With "All…" it is `disabled` and its only option reads **"Pick one project to filter by sprint"**. |
| Load tickets | Enabled once a product is set (an "All" scope is valid). It is no longer gated on `projectId !== ''`. |
| Scope wording | With "All…", `scopeDescription` = **"{Product} ({KEY1}, {KEY2})"**. The no-results line then reads e.g. "No tickets matched {Product} ({KEY1}), …", keeping today's sentence shape. |
| Unknown mapped key (R Pitfall 2) | For each mapped key missing from `useJiraProjects()`: `<p class="text-sm text-warning">` **"{KEY} isn't a Jira project you can see. Check the mapping in Portfolio › Products."**, with the link as in the notice. It shows under the control row. It does not block, because Jira may still answer. |
| Advanced: edit as JQL (D-05) | Unscoped and unchanged. Under the JQL textarea, a new helper line (Small, muted): **"Advanced JQL searches every project you can see, not only {Product}'s."** The placeholder stays as it is. |
| Selection, table, release-scope hiding | Unchanged |
| `onAction` | `(ticketKeys) => …`. The jiraProjectKey argument is removed (R). |

### 5. AddToReleaseDialog (D-01, D-02, REL-PF-02)

New props are `productId`, `productName` and `startWithForm` (= `new`). `ProductPicker` and `jiraProjectKey` are deleted.

| Mode | Contract |
|---|---|
| Title, add mode | **"Add {n} ticket(s) to a release"** (unchanged), then a new line (Body, muted, `mt-1`): **"Product: {Product}"** |
| Title, `startWithForm` | **"New release with {n} ticket(s)"**, then the same "Product: {Product}" line |
| Release list (add mode) | Open releases whose `products` contains `productId` only. Rows, filter input (>8) and **"Add"** buttons are unchanged. |
| No open releases for the product | The list is replaced by **"{Product} has no open releases. Create one below."** (Body, muted), and the form opens automatically (the existing zero-open behaviour). |
| `startWithForm` | The list, its loading and error states, and the **"New release…"** toggle are **not rendered**. The form is open on mount, and focus goes to "Release name". **(discretion)** |
| Form fields | **"Release name"** and **"Version"**, unchanged. There is no product control: the product is the read-only line under the title. |
| Submit | Add mode: **"Create & add"** (unchanged). `startWithForm`: **"Create release"**. Disabled while name or version is blank, or while pending. Pending: `Spinner` + **"Creating release…"**, `disabled`. |
| Payload | `{ name, version, ticketKeys, productId }` |
| Success | Navigates to the release (existing `goToRelease`). **No toast**: the release page is the feedback (Phase 23 toast rule). |
| Errors | All inline, as today: `RELEASE_DUPLICATE` copy unchanged, field errors under their inputs, everything else `messageForReason` with `role="alert"` and `data-reason`. That includes `PRODUCT_NO_JIRA_PROJECT` and `PRODUCT_ARCHIVED` as backstops. |
| Cancel | Unchanged. It closes the dialog, and selection stays on the Tickets page. |

### 6. AddTicketsToReleaseDialog (D-01)

- It passes `productId={release.products[0]?.id}` to TicketBrowser. The title **"Add tickets to {name} {version}"** and the action **"Add to this release"** are unchanged.
- When the release's product has no keys, the dialog body shows the D-17.2-04 notice instead of the browser, and only Cancel remains. This needs the product's keys from `useProducts()`.
- When the release has no product (legacy, should not occur): **"Choose a product for this release first."** (Body, muted) instead of the browser.

### 7. Release detail: product field (D-02, REL-PF-03)

`ProductsEditor` becomes a single-product editor. The file keeps its name; renaming it would churn imports for no gain.

| Element | Contract |
|---|---|
| Read row | **"Product:"** (Body 600), then one `PRODUCT_CHIP` with `{name}` (+ " (archived)"), or **"Unassigned"** (muted). Then the small button **"Change product"**, or **"Choose product"** when unassigned. |
| Blocked by installs (D-15-15) | When `release.products[0].hasInstalls`, "Change product" gets `aria-disabled="true"` and `aria-describedby` pointing to a visible Small `text-warning` line: **"Can't change: installs are recorded for this product on this release."** It stays in the tab order. Activation does nothing. |
| Panel | A `<fieldset>` with `<legend>` **"Product of this release"** (Body 600). One native radio per active product, plus the current product if it is archived, sorted A→Z. Radios are `size-4 accent-primary`, with label `{name}` (Body). A product with no mapped keys gets a Small muted suffix **" · no Jira project"**. It stays selectable, because the change rules allow it and only creation is blocked (D-04). |
| Actions | **"Save product"** (disabled while unchanged or pending; pending Spinner + **"Saving…"**) and **"Cancel"**. Escape cancels. On close, focus returns to "Change product". |
| Success | The panel closes. The sr-only `role="status"` announces **"Product updated."** No toast. The readiness pills go to "Out of date" on their own, because the server stamps `items_changed_at`. |
| Errors | Inline `role="alert"` + `data-reason` via `messageForReason`. The panel stays open with the choice kept. |
| Frozen | Editable (D-15-01). No status gate. |
| "Project: {key}" line | Unchanged. It records where the tickets were picked from (R Anti-patterns). |

## Accessibility

- **Labels.** The "Product" select has a `<label for>`. The scope helper and the JQL helper are linked with `aria-describedby`.
- **Live content.** The notice is `role="alert"` and announces once when the product changes. Loading lines are `role="status"`.
- **Blocked vs pending (kept from 15-23).**
  - Blocked uses `aria-disabled` + a visible reason (Change product).
  - Pending uses `disabled` + Spinner + a pending label (Create release, Save product).
  - The disabled Sprint select is a plain `disabled`, because its reason is its own option text.
- **Plain-text safety.** Product names and Jira keys are React text children. No `dangerouslySetInnerHTML`.
- **Test hooks.** `data-reason="PRODUCT_NO_JIRA_PROJECT"` on the notice; existing `data-reason` hooks are kept.
