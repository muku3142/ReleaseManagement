## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL -> login redirect | the `redirect` query parameter is attacker-controllable |
| user -> login form | credentials submitted to /api/auth/login |
| server -> document preview | rendered (sanitised) template HTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-23 | Spoofing (open redirect) | LoginRoute signed-in redirect and success path | mitigate | Both paths pass the param through the existing `safeRedirectTarget`; test proves an external URL falls back to the safe default |
| T-23-24 | Information Disclosure | login form | mitigate | Keep `type="password"`, `autoComplete` attributes and POST via existing `useLogin`; token help link uses `rel="noreferrer"` with `target="_blank"` |
| T-23-25 | Elevation of Privilege | site-not-configured guidance | mitigate | No unauthenticated settings path is added; copy points the operator to RM_JIRA_DEFAULT_BASE_URL instead of widening SecurityConfig (UI-SPEC Open item 1) |
| T-23-26 | Tampering (XSS) | RenderedDocument / TemplatePreview | accept | Only wrapper classes change; the existing sanitisation and `dangerouslySetInnerHTML` inputs are untouched (project template-security constraint unchanged) |
| T-23-27 | Repudiation | toasts replacing inline status | accept | Toasts only confirm visible-elsewhere successes; errors remain inline with role="alert" |
</threat_model>
