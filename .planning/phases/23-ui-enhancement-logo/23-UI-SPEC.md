### Owned-component edits applied on every `shadcn add`

These keep the contract consistent. The planner checks each one by property, not by grep count.
1. **Weight.** `font-medium` becomes `font-semibold` in every file under `components/ui/`. The 2-weight rule is in the Typography section.
2. **Focus.** The shadcn v4 focus treatment `focus-visible:ring-[3px] focus-visible:ring-ring/50 focus-visible:border-ring` becomes `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background`. That is a solid ring at 3:1 or better in both themes, and it continues the existing `ring-2 ring-blue-600` contract.
3. **Destructive button.** The text uses `text-destructive-foreground`, not `text-white`. The shadcn `dark:bg-destructive/60` is dropped: the dark destructive token already meets AA with its foreground.
4. **Sidebar persistence.** The `sidebar` component writes its open state to `localStorage["productops-sidebar"]` instead of the `sidebar_state` cookie. It is a SPA, and the cookie would ride on every `/api` request.

## Typography

Four sizes and two weights. The existing 400/600 contract is **kept**, not amended to 400/500/600. The 42 `font-medium` uses (BL Pillar 4) are drift to remove, and the owned shadcn components are edited to 600 (Design System edit 1). This keeps one rule across Phases 15–23 and gives a clear contrast between regular and emphasised text in Inter.

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|----------|
| Small (meta, helper lines, badges, table headers, kbd, captions) | 12px | 400; 600 inside badges and table headers | 16px (1.33) | `text-xs` |
| Body (default text, cells, inputs, nav items, buttons, toasts) | 14px | 400; 600 for labels, buttons, active nav, emphasised names | 20px (1.43) | `text-sm` |
| Heading (section `<h2>`, card titles, dialog titles, empty-state titles, login "Sign in") | 16px | 600 | 24px (1.5) | `text-base` |
| Display (page title `<h1>` in PageHeader; KPI figures from 23.1) | 24px | 600 | 32px (1.33), `tracking-tight` | `text-2xl` |

Rules:
- **Hierarchy (BL Top fix 2).** Every page has exactly one `<h1>`, the PageHeader title at Display 24/600. Sections are `<h2>` at 16/600. The shell no longer renders an `<h1>`: the sidebar lockup is a link, not a heading. This resolves the Portfolio `<h1>` clash (BL Visuals) in favour of "the page title is the h1".
- **Labels** are Body 14 at weight 600.
- **Dashboard tile figures.** In 23.1 they move from 18 to the Display 24/600 + `tabular-nums` step. 18px (`text-lg`) leaves the scale.
- **Exceptions outside the scale**:
  - the brand wordmark (18px and 30px at 800 in the brand font): logo artwork
  - rendered-document content inside the `.paper` surface (for example the `text-2xl` cover): document content, not UI
- `font-mono` stays for keys/code in existing spots at Body or Small size. It is a family, not a weight.

### Dark variant and the paper surface

- `@custom-variant dark (&:where(.dark, .dark *):not(.paper, .paper *));`
- `.paper` re-declares the light token values and `color-scheme: light`. Custom properties set on the element override the inherited dark values.
- `.paper` is applied to:
  - the rendered-document preview (`RenderedDocument`, `TemplatePreview`): with `bg-white text-zinc-950`, `prose` (never `prose-invert`), a 1px `--border` page edge and `shadow-xs`
  - uploaded template-logo previews
  - the **interim content island** (below)
- Generated documents are never themed (D-23-06).

### Interim content island (Phase 23 only, removed by the last 23.1 plan)

- Routes not yet migrated still use raw `bg-white`/`gray-*` classes (D-23-05). In a dark shell, they render inside a `.paper` `<main>`, so they show as a light page in a dark frame, not as a white-on-dark collage.
- Mechanism: migrated routes set `staticData: { themed: true }`, and `AppShell` adds `.paper` to `<main>` when the deepest match lacks it. In Phase 23 only `/releases` sets it.
- 23.1 sets it per page as each page migrates, and deletes the flag and the check once every route is migrated.

## Theme (UI-02, D-23-06)

- **Values**: `light | dark | system`. Default is `system`.
- **Storage**: `localStorage["productops-theme"]` (per browser). This is the only `localStorage` key besides `productops-sidebar`. Earlier "no browser persistence" rules (17, 17.1) covered page state, not preferences.
- **Boot script.** An inline script in `index.html`, run before CSS paint, so there is no light flash on dark systems. It reads the key, resolves `system` through `matchMedia('(prefers-color-scheme: dark)')`, sets `class="dark"` or removes it on `<html>`, and sets `style.colorScheme`. If a CSP is added later (Phase 24), this script is allowed by hash.
- **System following.** While the value is `system`, a `matchMedia` change listener flips the class live.
- **Toggle**:
  - Placement: in the top bar, as a ghost icon button `size-9` showing `Sun` (light) or `Moon` (dark), with `aria-label="Change theme"`.
  - It opens a DropdownMenu radio group with the items **"Light"** (`Sun`), **"Dark"** (`Moon`) and **"System"** (`Monitor`). The current value is checked.
  - The same three choices are in the palette.
- **Theme switch transition.** None: the colour change is instant. A theme switch must not animate every surface.

## Toasts, skeletons, spinner and motion (UI-04, D-23-07)

### Toaster

- One `<Toaster>` at the root, used for both signed-in and login (login does not toast today).
- Settings:
  - `position="bottom-right"`
  - `visibleToasts={3}`
  - `closeButton`
  - `duration={5000}`

- Icons are lucide in status colours: success `CircleCheck` `text-success`, info `Info` `text-info`, warning `TriangleAlert` `text-warning`, error `CircleX` `text-destructive`.

### When to toast (rule for every phase)

| Situation | Treatment |
|---|---|
| A mutation succeeded and the change is visible on screen | **No toast.** The UI change is the feedback (as today for inline edits). |
| A mutation succeeded and the result is not visible, or the user moved away | `toast.success("<Thing> <past tense>.")` with the copy from the page's UI-SPEC |
| A reversible removal | `toast("<Thing> removed.", { action: { label: "Undo", onClick } , duration: 8000 })`. Undo re-runs the inverse mutation. If Undo fails, `toast.error` shows the `messageForReason` text. |
| A partial-failure result the user must read (for example the roadmap add result) | `toast.warning(..., { duration: Infinity })`, dismissed only by its close button |
| An error caused by a control the user just used | **Not a toast.** It stays inline, `role="alert"` beside the control, as today (BL Pillar 6). |
| A background error with no anchoring control | `toast.error` |

- Sonner's region is `aria-live="polite"`. When a message moves to a toast, the old sr-only duplicate for that message is removed so it is not announced twice.
- Toasts never carry the only copy of essential information.

**Phase 23 proof: `SettingsRoute.tsx` only.** These three inline green texts are replaced:
- "Saved." becomes **"Jira site saved."**
- "Token replaced." stays **"Token replaced."**
- "Azure DevOps settings saved." stays **"Azure DevOps settings saved."**

The BL contrast failure (`text-green-600`) goes with them. The other Settings sections (Briefings) migrate in 23.1.

### Skeletons

- `<Skeleton>`: `bg-muted rounded-md animate-pulse`, `aria-hidden`. The loading container carries `role="status"`, `aria-busy="true"` and sr-only text, e.g. **"Loading releases…"**.
- Use skeletons for **first loads** of page-level data: tables (5 rows of 3 cell bars sized to the columns), cards and tiles (a figure bar 24px tall and a caption bar).
- Use `<Spinner>` + text for in-place actions (pending buttons, refreshes), as today.

### Spinner

- The 5 hand-rolled spinner definitions are replaced as pages migrate (23.1).

### Motion tokens (discretion: durations and easing)

| Use | Duration | Easing | Effect |
|---|---|---|---|
| Hover, press, colour | 150ms | `ease-out` | colour and background only |
| Menus, popovers, tooltips, palette, dialogs (enter) | 200ms | `cubic-bezier(0.16, 1, 0.3, 1)` | fade + `zoom-in-95` (tw-animate-css defaults in the shadcn components) |

## Interaction and Accessibility

- **Landmarks.** `nav` (sidebar, `aria-label="Main"`), `header` (top bar), `main#content`. There is one `h1` per page.
- **Focus.**
  - Every interactive element shows the solid `ring-2 ring-ring ring-offset-2` on `:focus-visible`.
  - No component removes the outline without that replacement. The BL template textarea blocker is fixed in 23.1 by this same rule.
  - After closing any menu, popover, sheet, dialog or the palette, focus returns to its trigger. After navigating from the palette, focus moves to `main#content`.
- **Keyboard.** Tab order: skip link, sidebar items, top bar (sidebar trigger, palette trigger, theme, account), then the page. Every shell control is reachable and operable by keyboard. Tooltips appear on focus as well as hover and never hold essential information.
- **Contrast.** All text pairs above are 4.5:1 or better and all non-text pairs (focus ring, ladder, chart marks, input borders against labels) are 3:1 or better, in both themes. The figures are computed in the Color table.
  - Exceptions: brand artwork, where the white glyph over the sky end of the gradient is about 2.1:1. It is a logo, not text or UI state.
  - Disabled controls, at `opacity-50`.
- **Status.** Colour is never the only signal (words on every badge, shapes on the ladder, labelled chart values).
- **Live regions.** The Sonner toaster (polite), the DataTable count (polite) and loading containers (`role="status"`). Errors are `role="alert"`.
- **Blocked vs pending (kept from 15–17.1).**
  - Blocked actions use `aria-disabled="true"` + `aria-describedby` to a visible reason, and stay in the tab order.
  - Pending uses `disabled` + Spinner + a pending label.
  - The shadcn Button must forward `aria-disabled` and must suppress `onClick` when `aria-disabled="true"` (an owned edit, added in 23.1 when the first blocked Button appears).
- **Plain-text safety (kept).** Palette labels, release, client and product names and roadmap titles render as React text children. No `dangerouslySetInnerHTML` outside the existing sanitised `RenderedDocument`.
- **Responsive.**
  - Desktop-first.
  - Below `md`: the sidebar becomes a Sheet, the palette trigger collapses to an icon, top-bar icon buttons grow to 44px, the DataTable scrolls horizontally with the sticky first column, and toasts span the width (Sonner mobile default).
  - Login is usable at 320px wide.
- **Reduced motion.** The global rule plus Recharts and scroll handling, as in the motion section.
- **Interaction rules 23.1 must keep.** Every **[K]** item in 23-UI-BASELINE.md's per-page checklist is binding, plus the Interaction and Accessibility sections of 15-, 16-, 17- and 17.1-UI-SPEC. In particular:
  - URL-driven tabs (`replace: true`, roving focus)
  - FilterTile `aria-pressed` and focus return
  - ProductFilter Escape/outside-click with focus return and immediate apply
  - InputCell one-input-one-save, with Escape to revert
  - confirms close on `onSettled`
  - the unfreeze blocked reason
  - `#ticket-KEY` matched against loaded keys only
  - the `beforeunload` guard on template edits
  - `data-status` / `data-state` / `data-reason` test hooks

## Addendum: Motion and hover (D-23-14, D-23-15, added 2026-10-26)

The user asked for more motion and hover feedback. These rules extend the "Motion" contract above and do not replace it. The global reduced-motion rule turns all of them off.

| Token | Value | Use |
|---|---|---|
| `--motion-fast` | 120ms | hover colour/shadow, button press |
| `--motion-base` | 200ms | page fade-in, nav indicator slide, card lift |
| `--motion-slow` | 600ms | logo connect-in, KPI count-up (max) |
| `--ease-out` | cubic-bezier(0.22, 1, 0.36, 1) | all entrances and slides |
| stagger step | 30ms per row, capped at 10 rows (300ms) | list and table entrance |

**Hover**
- **Table rows:** `bg-primary/5` on hover. Clickable rows also get a 2px left accent bar (`shadow-[inset_2px_0_0_var(--primary)]`). Sticky cells must pick up the hover background (baseline finding).
- **Cards and tiles:** with the `interactive` Card prop, hover gives `-translate-y-0.5`, `shadow-md` and a `border-primary/40` border. Non-clickable cards don't lift.
- **Nav items:** `bg-sidebar-accent` on hover. The active item has an indicator bar that slides between items (transform only, `--motion-base`).
- **Buttons:** hover brightens (`hover:brightness-110`, or the variant's hover colour). `active:scale-[0.98]` gives the press.
- **Links:** an animated underline grows from the left (a `background-size` transition). Focus-visible still shows the ring.

**Animations**
- **Page:** `<main>` content fades and rises 4px on route change.
- **Lists:** rows in DataTable and the dashboard lists stagger in on first render only, never on re-sort or filter.
- **KPI numbers:** count up from 0 on first load (≤600ms). The final value is in the DOM from the start (`aria-live` off) so screen readers and tests read the real number.
- **Charts:** Recharts bar animation on first load only (`isAnimationActive` respects reduced motion, as before).
- **Status change:** a Badge or ladder dot pulses (a scale 1→1.15→1 ring) once, when its value changes after mount, never on first render.
- **Logo:** `ProductOpsMark` with `animate` draws its four links, then pops the nodes in (stroke-dashoffset and scale, ~600ms). It runs once per page load, on the login page and the app shell's first mount.
