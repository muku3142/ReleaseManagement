<objective>
Fix two confirmed defects in `AdfFlattener` that corrupt every generated document containing
the `{{description}}` placeholder:

1. `heading` is an unhandled node type — it falls through to `default`, emitting bare text with
   no `#` prefix and no trailing newline, so the heading merges into the next block
   (`DescriptionWhen sending an MT192...`).
2. The `codeBlock` closing fence is appended without a preceding newline, so content and fence
   share a line (`` :79:/AGNT/``` ``). CommonMark never recognises the fence, the block never
   closes, and it swallows the remainder of the document.

Purpose: `{{description}}` is the only field carrying multi-block ADF, so both defects are
invisible until a template uses it — and then they destroy the whole document.
Output: two node cases corrected in `AdfFlattener.java`; one wrong test assertion corrected and
heading coverage added in `AdfFlattenerTest.java`.

**Explicitly NOT in this plan** (do not "improve" these while in the file):
- Blank-line separation between consecutive paragraphs — current single-`\n` behaviour is
  unchanged.
- Any ADF node type other than `heading` (table, panel, media, mention, emoji, status stay on the
  `default` degrade branch per D-02-04).
- `MAX_NODES` / `MAX_DEPTH` bounding logic.
- The template-authoring indentation issue (unindented `{{description}}` under the
  `- **{{title}}**` bullet) — that belongs with plan 05-09.
- Anything in `frontend/` — another agent is working there concurrently in a separate worktree.
</objective>

Edit `AdfFlattener.java` only — two changes inside the `walk` switch, nothing else.

1. **Add a `heading` arm** next to the `paragraph` arm:

```java
case "heading" -> {
    int level = Math.clamp(node.path("attrs").path("level").asInt(1), 1, 6);
    out.append("#".repeat(level)).append(' ');
    walkChildren(node, out, listDepth, depth + 1, state);
    out.append('\n');
}
```

`Math.clamp` is JDK 21+ and the project baseline is Java 25. The clamp exists solely to keep the
class's never-throw invariant against a malformed `level` (`"#".repeat(0)` swallows the marker,
a negative throws) — do not extend it into broader validation.

2. **Terminate the codeBlock content before the closing fence.** In the `codeBlock` arm, after
`walkChildren` and before the closing `` "```\n" ``, append a newline unless the buffer already
ends with one (text nodes append raw text with no trailing newline; a trailing `hardBreak` or an
empty code block already supplies one, and a doubled newline would inject a blank line into the
block):

```java
case "codeBlock" -> {
    out.append("```\n");
    walkChildren(node, out, listDepth, depth + 1, state);
    if (out.charAt(out.length() - 1) != '\n') {
        out.append('\n');
    }
    out.append("```\n");
}
```

`out` is guaranteed non-empty at that point because the opening fence was just appended, so the
`charAt` needs no length guard.

Do not touch `paragraph`, `listItem`, `default`, `bounded`, or `applyMarks`. `listItem` still
gets its trailing newline from its child `paragraph`; the existing bullet/nested-bullet tests are
the regression check for that — they must stay green untouched.
