# Quick 261026-l31: calculated Reach, Impact and Confidence with reasoned overrides

Reach is now calculated at read time from the install ledger (non-archived clients whose current release of the item's product is a success). Impact and Confidence for Jira items come from the stored Jira priority and the sprint-check readiness signals. A user can override any calculated value with a 1-200 character reason, or reset it, and each override or reset is a history row.

## Commits

- 727ad05 feat(roadmap): calculate Reach from installs and let users override calculated RICE values with a reason
- c259f02 feat(roadmap): derive Impact and Confidence from Jira priority and readiness, expose overrides
- 1b01111 feat(roadmap-ui): show calculated RICE values with override and reset

## What changed

- V21 adds `jira_priority`, `jira_readiness`, three `*_override_reason` columns with CHECKs that pair a value with its reason, plus `kind`/`reason` on the history table.
- Domain: `RiceCalculation` (priority/readiness mapping, calculated, effective, isCalculated), `RiceEdits` (entered/override/reset -> `InputUpdate`), and `RoadmapRanking.rank(items, runningClientsByProduct)` now scores on effective values.
- `RoadmapRepository.updateInputsUnderLock(id, decide)` replaces `setInputsUnderLock`. History rows come from `RiceEdits`, not from the adapter.
- `PortfolioReadRepository.runningClientCounts()`: one static native query over `current_client_release` joined to `client`.
- Imports: add-from-Jira, add-from-release and refresh make one batched briefing search per 100 keys in the fetch phase, before any write. A refreshed issue that is missing from the result keeps its stored facts. `FieldMetadataService.briefingFieldIds` is now shared with `BriefingRunner`.
- API: `PUT/DELETE /api/roadmap/items/{id}/overrides/{field}`. `/inputs` no longer takes reach and rejects impact/confidence on Jira items (`ROADMAP_FIELD_CALCULATED`). The response gains `calculated`, `overrides`, `calculatedFields`, `jiraPriority` and `readinessSignals`. History entries gain `kind` and `reason`. The CSV gains an `Overridden` column.
- UI: `InputCell` hands calculated fields to the new `OverrideCell` (read-only value, Calculated/Overridden marker, Override form with required reason, Reset to calculated). The history panel labels override and reset rows, and the rubric describes the calculation.

## Deviations from Plan

**1. [Rule 3 - Blocking] BriefingRunnerTest stubs moved to `briefingFieldIds`**
- `BriefingRunner` now calls `fields.briefingFieldIds(ctx)`, so the test's `resolveOptional` stubs and verifies were changed to the new method. Behavior is unchanged. A `FieldMetadataServiceTest` case covers the moved mapping.

**2. [Rule 1 - Bug] Ranking fixtures with a null product**
- The old `RoadmapRankingTest` fixtures used `productId = null`, which is invalid since kyg, and `Map.getOrDefault(null)` throws on it. Gave them a product.

**3. RoadmapFlowIT does not record a real install**
- The flow IT mocks `JiraBriefingPort` and `FieldMetadataService` (it already mocked `TicketSearchService`). It covers calculated Impact/Confidence, Reach 0 for a product nobody runs, override, reset and the history kinds. The Reach-from-installs query is covered by `PortfolioReadPersistenceIT` against real views, and the ranking/service wiring by unit tests. A full install recording through HTTP inside the flow IT was left out.

**4. `RoadmapInputsRequest` no longer has `reach`**
- An old client that still sends `reach` has it ignored (Jackson ignores unknown properties). It is not rejected.
